## 一、链通了没通：两档都通

### 第一档 回复里的 Mermaid + 表格

六组全部产出，且全部用**真的 mermaid**（`@mermaid-js/mermaid-cli`，mermaid 11.17.2）渲染成功，rc=0。

**版式是量出来的，不是挑的。** 同样 72 节点，三种写法的自然尺寸：

| 写法 | 自然尺寸 | 判 |
| --- | --- | --- |
| `flowchart LR` + subgraph 内 `direction TB` | 19854 × 193 | 103:1 的带子，废 |
| `flowchart TB` + 模块不相连 + 内部 `TB` | 346 × 10334 | 0.03:1 的柱子，废 |
| `flowchart TB` + 模块间 `~~~` + 内部 `LR` | 3182 × 2294 | 1.4:1，能看 |

机制：**没有边的节点，Mermaid 一律排成一行，`direction` 管不住它**，得靠 `~~~` 隐形边掰。
于是第一档的整图版依赖 `~~~`（mermaid ≥ 9.4）与 subgraph `direction`（≥ 9.0）——宿主的 mermaid 版本是个前提，落笔时得记一条。

**转义只要一条**：`"` → `#quot;`。11 个刁钻标题（`#`、`%`、`<>`、`&`、`[]`、`{}`、`|`、反引号、`~~~`、`\`、`/`、`end` 这个关键词本身、60 字长标题）全部渲染正确，无一条 parse 失败。节点 id 用 `图视图.json` 的 id 洗成 ascii，不碰标题。

**体量**（在办中，72 节点）：

| | 字符 |
| --- | --- |
| 源 `图视图.json` | 20,651 |
| 整图版 mermaid 块 | 6,952 |
| 整图版整份回复 | 12,259 |
| 概览版 mermaid 块 | 1,412 |
| 概览版整份回复 | 6,719 |

呈现物把 20.6k 压成 6.7k–12.3k。但**渲染的是回复，不是工具输出**：这 6.7k–12.3k 得由模型逐字打进回复里才出得来图。照 #123 的分段，「写长文本」占段 2 的 55%——这是第一档每次调用的固定成本，给 #133 当输入。

**空图那一格整图版是空的**：`空图` 渲出 16 × 16 的白板。整图版缺一条空图分支；概览版有（画成「前方 12 个模块尚未进图」，11.5 KB 的 PNG）。

**陈旧提示可用**：`touch 图.json` 之后，两档都报「视图比源图旧」。#128 的「只报不修」用 mtime 比较就够。

### 第二档 随包零依赖 tkinter 窗口

开得起来，实测截图 1196 × 759：标题栏是案件名、案件根那一行、案件切换下拉、12 模块 72 节点的树（状态填色 / 来源 / 时限 / 文书版本四列）、右边详情面板与「打开最新文书」。

**AFK 自检**（`window --selftest`：每个案件切一遍、每个节点点一遍、开文书那道闸门干跑一遍）：

```
在办中      节点  72  可开文书  2  被拒 0
整块不走     节点  72  可开文书  1  被拒 0
空图        节点  72  可开文书  0  被拒 0
自加节点     节点  73  可开文书  1  被拒 0
跳着走      节点  72  可开文书  2  被拒 0   陈旧提示='视图比源图旧…'
自检完：被拒合计 0
```

**进程寿命 = 窗口寿命，零残留**：开窗时两个进程（`python3.9.exe` 垫片 5,080 K + `python.exe` 28,292 K），关窗三秒后 `tasklist` 里一个都不剩。

**cwd 锁目录是真的，一行 `os.chdir` 就解，而且必须解**：

| | 开着窗口改名工作区 |
| --- | --- |
| 不 chdir（cwd 留在工作区） | `Device or resource busy` ——**失败** |
| chdir 到 home（原型的做法） | 工作区、skill 目录、案件根三者**都能改名** |

#127(a) 那条「窗口 cwd 不落 skill 目录与工作区」从此不是约定而是一行可执行的代码，并且 #126 记的「Windows 锁住进程 cwd 会让整目录替换式升级直接失败」在这个形态上**确实会咬人**——不写那一行就咬。

## 二、接口缺哪几样：#128 的结论在真数据上全部成立

| #128 的裁定 | 真数据上 |
| --- | --- |
| 够画，引擎与插件谁都不补一个字段 | **成立**。72 节点上模块→节点树、`状态`、`来源`、`前方`两值、`时限` 原文、`文书版本` 六样全用上了，没缺过一样 |
| 案件名 = 工作区目录名 | **成立**。两档都 basename 取到，案号一次都没碰 |
| 一致性只报不修（比 mtime） | **成立**，跑通 |
| 打开文书只许视图里列出的相对路径、且解析后仍在工作区内 | **成立**，6 次干跑 0 拒 0 逃逸 |
| 第一档只认 cwd，不接受任何指定工作区的参数 | **成立**，`--workspace` 直接 `unrecognized arguments` |
| 第二档接一个案件根、现扫 `*/图视图.json`、根记在 `~/.loo0ng/` 一行 | **成立**，五个案件扫得到、切得动 |

真数据上新冒出来两条，都**不是字段缺口，是呈现缺口**，归界面设计那一摊（本图 Out of scope），记在这里给它当第一份输入：

1. **模块状态三值在真案件开局全是「进行中」**（12/12）。概览版按模块状态上色等于整排同色，颜色这个维度在开局是废的；要分辨只能靠节点状态计数（原型已经把 `○●·` 计数打进标签）。
2. **配色里「未生成 `#f4f4f5`」与「不适用 `#e4e4e7`」肉眼几乎同色**。
