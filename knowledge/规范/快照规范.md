# 快照规范

`快照/` 目录下有两类互不相同的产物，本规范定义两者：
**进度快照**（`快照-YYYYMMDD-HHMM.md`，只增不改）与**流程图谱快照**（`流程图谱.html`，覆盖重生成）。

## 进度快照

进度快照是案件进度的不可变表达。新材料到达、文书批准、节点标记等事件产生**新快照文件**，旧快照永久保留、不修改不删除。

## 文件

`快照/快照-YYYYMMDD-HHMM.md`，一事件一文件。

## 结构

```markdown
# 快照-<时间戳>

- 案件：<案件名>
- 生成时间：<时间>
- 触发事由：<导入材料 N 件 / 批准文书 X / 节点标记 Y / …>
- 依据流程模型：knowledge/流程模型/<业务类型>.md（版本按仓库当时状态）

## 已完成节点
| 节点 | 标记时间 | 依据 |
（仅以 节点标记.md 为据；回执、材料齐备、模型推断均不构成完成）

## 活动任务节点（全部可推进项）
| 节点 | 排序提示（前置情况） | 期限轻提示 | 对应文书 |
（前置条件只作排序与提示，不决定可否推进）
（每条以流程模型编号领起，如"节点 3.5 债权实质审查"；须每次列全，不得回指旧快照）

## 主要下一任务
**节点 X.Y <节点名称>**：<推荐理由；律师可以选别的>
（正文须以粗体节点编号领起，之后才写理由）

## 材料缺件提示
<只展示不阻塞；无则写"无">

## 备注
<本次快照相关的其他观察，如回执带来的信息纠正>
```

## 铁律

- 快照不自行判定"完成"：已完成节点一律抄自 `节点标记.md`。
- 期限轻提示：法定期限固定与个案无关，不顺延节假日，逾期不阻塞。
- 不存在"唯一当前阶段"：活动任务节点可以并存多个。
- **不得回指**：不许写"其余节点状态与 快照-XXXX 相同"。活动任务节点每次列全；快照生成脚本不解析散文、不追溯旧快照。
- **节点编号可字面提取**：活动任务节点与主要下一任务两节里的节点，须以 `节点 X.Y` 形式出现。流程图谱据此打高亮环与星标；抓不到就只是不打标，不影响其余功能。
- 快照不承载节点状态：四态由 caselib 从 `节点标记.md`、`批准记录.md`、`版本记录.md` 推导（见 `docs/adr/0003-节点状态由登记文件推导.md`）。

## 流程图谱快照

`快照/流程图谱.html`，自包含 HTML，每次**覆盖**重生成（不是只增不改，与进度快照相反）；页眉带生成时间、案件 rev 与未归档新文件数。

**重生成命令（唯一口径，改这里就够）**：

```
python <skill 仓库根>/lib/snapshot.py <案件目录>
```

- `<skill 仓库根>`：本规范文件所在仓库的根（本文件在其 `knowledge/规范/` 下，上溯两级即是）。
  脚本自行解析依赖，**与当前工作目录无关**，给绝对路径最省事。
- `<案件目录>`：案件目录绝对路径，或相对案件工作区根的案件 id。

**谁负责跑**（ADR-0007 裁定 1：律师永不主动想这件事）：

- 四件律师动作脚本（批准 / 节点标记 / 分支适用裁定 / 律师陈述）落盘收尾自动跑，脚本内已内置；
- 写案件登记文件的编排 skill——`import-archive`、`draft-document`、`claim-review`——落盘收尾跑一次。

**与 Codex 会话内 widget 的分工**（ADR-0008）：同一份图数据两个出口。widget 是 Codex 侧的
查看主出口（会话内实时推导，不落盘）；本节这份落盘快照是**平台无关兜底**，Claude 侧、
无插件环境、以及日后回看都靠它。**两者不互相替代**——开着 widget 也照跑本节的重生成，
不跑就等于案件工作区里没有留痕。律师动作落盘后 `lawyer-actions` 另有一条刷新 widget 的
收尾义务，那是刷新屏幕，不是落盘。

**铁律**：

- 重生成失败**不回滚**已落盘的内容（归档、文书版本、动作行都已成事实），如实报出错误，不假装成功；
- 产物只落案件工作区，**不得发布到 claude.ai Artifact 或任何外部服务**（ADR-0007 红线：节点名与文书名是案件敏感信息）；
- 落盘位置原样告知律师，不摘要。
