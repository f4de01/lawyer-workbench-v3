新增编排 skill `loo0ng-doit`（办节点，user-invoked 双旗）：律师在案件工作区打一句自由文本 = 动作 + 节点 + 补充，一个对话只服务一个节点（ADR-0008、ADR-0010）。拍板与兜底先行，主循环不靠生成就能走通：「确认 X」「X 不适用」「模块 Y 不适用」经图引擎落一条原样存着律师那句话的条目，三条留痕规则（原话原样存、只在律师明确说出且指向本节点时落、同一对话第二次出一版指向另一节点即拒绝）替代入口门；「X 我自己写好了」先归档，对 DOCX 跑一次只披露不阻断的门禁，按 `references/兜底件审查报告.md` 写报告，再登记为已生成、来源律师，文书一个字不改。出一版的顺序定死：开场归档、复制律师指的文件（别案成品剔除案件内容后进 `模板/生成/`）、惰性建节点、材料指南空白模板三样全无则只回缺什么且不算生成失败、整读、写 Markdown 最小集、转换、门禁、落盘 `文书/<节点标题>/` 三件、追加带三条相对路径的生成条目、回显审查报告要点与收尾两行；门禁不过改稿重转至多 2 次，仍不过就生成失败、不落盘、不追加条目。生成不问缺事实，缺项进审查报告的待律师裁定，律师在对话里答一句先落成陈述（`--reply` 指向那份报告）再重出，仍在同一回合。本 skill 没有自己的脚本，图、归档与陈述、转换与门禁分别经 skill "loo0ng-graph"、skill "loo0ng-filing"、skill "loo0ng-to-docx" 的 CLI 落盘。#28 真实触发暴露的两处空白一并定死并写进两件 skill 的正文：落进 `文书/<节点标题>/` 的就是一次生成（三件加一条条目，缺一即生成失败），律师只说「转成 word」「检一下」时不落进 `文书/`、不写审查报告、不动图；生成条目只有本 skill 一条来路，参考 skill 被够到之后不自行追加条目、不自己补写审查报告。另交付种子「兜底」与五个用例（拍板、模块不适用、换节点被拒、兜底登记、办节点出一版），`tests/loo0ng-doit/test_seeds.py` 验种子状态；eval 跑器删临时工作区改为退避重试（门禁起的 Word 会多攥一会儿刚检过的件）。
