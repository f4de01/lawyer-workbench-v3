关票触发改在从种子生出的临时工作区里做（#66）。原先的做法是在 Cases 根下常驻两个合成工作区、每次关票都在它们上面触发，这既不是 ADR-0009 说的真实案件、也不是 ADR-0015 说的只生不存，两头不挨着且没写下过规矩；而触发要改图、改图不可逆（节点永不删、不适用是终态，ADR-0003），留下的痕走支持的路子撤不掉，撤只有标不适用（残渣更多）或手改 JSON（不受支持）两条，攒几轮那两个「现成起点」就既不像刚起手也不像办到一半。改法照票里定的甲案：漂移不被管理而被根除。`scripts/skill-eval.py` 加 `--materialize <种子名>`，生一个回放了该种子的工作区、打印路径就停，不跑 harness 也不删（生出来是给人接着用的），`--harness` 因此改为非必需，跑用例才有意义的参数（`--harness`、`--case`、`--runs`、`--keep`、`--max-turns`、`--timeout`）与它一并互斥，给了就报错说清是哪个，不静默吃掉；`tests/skill-eval/` 加七条，旧的 `test_harness_is_required` 名字已失真、断言与新那条重复，删掉。ADR-0009 的完成定义随之改口径（关票触发以临时工作区为准，真实案件不再是关票的前提，其余不变），ADR-0015 把「只生不存」的适用范围延伸到关票触发，两处各写一条同日附注。`docs/agents/skills.md` 补「关票触发怎么做」一段：挑哪个种子、一条命令生工作区、Claude Code 侧那行可照抄的 `claude -p`、Codex 侧只能人工（`$名` 在 AFK 下不解析，`codex debug prompt-input` 可复核）、用完删、路径不进 issue。`CONTEXT.md`「测试工作区」词条补「关票的真实触发也在其中做」。两处局限照实写进 `docs/agents/skills.md`：Claude Code 侧那行触发命令与跑器给这一侧拼的是同一条，两道门在这一侧几乎重合，增量大的是 Codex 侧（那边 eval 用替身提示词、根本没测触发）；关票评论里「验到什么」的话术也改准了 —— 验到的是这条安装路线下按名字触发（Claude Code 侧 junction 裸名、Codex 侧客户端带前缀名），插件路线的 `/loo0ng-skills:<名>` 不在此列。Cases 根下那几个常驻合成目录按律师的话留着，但不再承担任何门槛，只作手工探索的起点。
