起手取活图路径改成机械的：`init` 自己调 `home`（#97，ADR-0019）。

#90 把领域目录搬出 skill 包之后，起手取活图路径这一步是**靠正文驱动的两条命令**：模型先跑 `sketch.py home --name <领域名>` 拿路径，再把它给 `setup.py init --domain`。跳掉第一条的后果正是 #90 存在的理由本身：指针块记下包内出厂种子的路径，律师此后累计在领域目录上的东西下一次升级照样被抹掉；而起手一案一次（ADR-0007），要改只能把工作区整个删掉重来。这是 #65 那一族的同一句教训：**要求写在了模型走不到的地方**。

本票在票里给的两条路中取**路 A**：`init` 自己调 `home`，正文里那一步彻底消失，模型没有可跳过的东西。路 B（对包内种子路径直接拒、留 `--allow-seed` 逃生口）改动面更小，但它把这一步仍留在正文里，只是把跳过的后果从"事后一句提醒"改成"事前一次拒绝"；而且它会与 ADR-0020「起手那一头不动，`setup.py` 对包内种子仍只报不拒」当面撞上。路 A 不碰那一条。

`setup.py init` 多一个 `--domain-name <领域名>`：律师侧只打一条命令（`init --full --domain-name 破产`），活图目录由 `setup.py` 子进程调 skill "loo0ng-domain" 的 `sketch.py home` 取回，`home` 的回显原样带给律师（首次起手拷了几件看得见）。这与它子进程调图引擎是同一个形状：活图仍归 `loo0ng-domain` 管，`setup.py` 只是调用者，不自己算活图在哪、也不自己拷种子。`--domain <路径>` 原样保留给开发侧（种子回放、开发者手上那份定制的领域目录），两者二选一、同时给即拒。

`home` 拒（这个领域既没有活图、包里也没有种子）时起手跟着拒，发生在建格与落图之前：**一格不建、一个字不写**，律师原地改成空图起手（`--empty --name <领域名>`）即可。`--sketch` 与既有的 `--engine` 同一个用途，给装在别处时指路。

领域名不要给两遍：`--domain-name` 与 `--name` 同给即拒（两个给成不一样的，指针块的「领域」与「领域目录」会各指一处）。三选一的形状一个字没动：定制图自带领域名，`--domain-name` 对它仍是可选的。

`tests/loo0ng-setup-case/test_setup.py` 新增一组（`一条命令Case`）：一条命令起手后指针块记的仍是活图、首次起手经这一条命令就把出厂种子的三样拷出来、两种传法同时给即拒、取不到活图时一格不建一个字不写、给了 `--domain` 就根本不去碰活图家、定制图也能只给领域名、领域名给两遍即拒，外加一条钉两端回显契约的（`活图：` 这个前缀两件 skill 各持一份字面量，互不 import）。首次拷种子那一条用 `--sketch` 指一份合成的假包，真的 `assets/` 一个字节不碰（ADR-0015）。`loo0ng-setup-case` 与 `loo0ng-domain` 的正文、用例「起手」的说明、`docs/交付/现场清单.md` 段 3.4 跟着改；`sketch.py home` 本身与活图的位置一个字没动（票的边界）。
