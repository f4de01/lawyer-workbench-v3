包内出厂种子谁都不许写（#99，ADR-0020）：`graph.py` 对 `--kind domain` 落在 skill 包内的写**无条件拒**，没有放行口。挡的是 ADR-0019 与 #90 合起来留的一个洞——0.1.0 起手的工作区指针块指着包内种子，#91 把逐节点回流的路开出来之后，在这样的工作区里确认一次就会把律师累计的节点写进随包分发的那份文件，下一次 skill 包升级整个换掉；而律师那台机器上没有 git、没有隐私钩子，丢失是静默的。

裁定比堵洞高一层：**领域图的构建，开发侧与律师侧走同一条路**。开发者要定制或维护一个领域图，也是办一遍、逐节点回流进自己那份活图。所以引擎里不需要"开发侧放行"那个分支——原本设想的 `--seed` 旗标没有采用。出厂种子改由**入库**更新（活图那份 `领域图.json` 进仓库，一次 git 提交，经隐私钩子与第二双眼），它与 skill 包的版本发布是两回事。

**只拦写，不拦读**：`validate`、`views`，以及案件图拿种子当领域图来源（`--domain` 指着它起手、算前方、惰性带入）一条不碎——那是 eval 的回放助手与所有 0.1.0 工作区每天在走的路。这条规则**只管 `--kind domain`**：案件图落进包内是另一条硬边界的病，且该在起手那一刻拦。判据两条取或，与 `loo0ng-setup-case` 的 `setup.py` 同源（按脚本位置算出的兄弟 `assets/`；目录名摆成 `<…>/loo0ng-domain/assets/<领域名>`），两处各留一行互指注释；不加"祖先里有 `.git`"这条，它会误伤把活图放进 git 备份的律师。

拒绝消息把出路一次说全：活图在哪、路径怎么取、这个工作区 `AGENTS.md` 里「领域目录」那一行怎么换。`loo0ng-doit` 正文补一条：被拒时**提案照样回显**，照实转告，**那一行由律师自己改，别替他改**。`loo0ng-graph` 正文里"出厂种子只在开发会话里改"改掉——开发会话也不行。起手那一头一个字没动（`setup.py` 仍只报不拒）：洞在写入那一刻已经堵死。

`CONTEXT.md` 三处：「领域图」与「回流」的终点统一成活图，「第二双眼」守的那次写从回流挪到入库，新增「入库」词条。

守住它的是脚本层 15 条断言加一条 eval 用例。**两侧都不碰仓库里真的 `assets/`**：拒的行为拿临时假包测（判据 ② 认得它的形状），真包只留一条只读断言钉住"它确实落在判据 ① 的射程里"，两条合起来才等于"包内种子字节不变"——拿真包跑就是拿开发者的工作树赌一次规则。eval 用例「指针指着种子被拒」测模型那一侧：确认照样落在案件图上（这条守门不该把办案挡住）、种子逐字不变、提案照样回显、回复里说清活图与那一行、没替律师改那一行、没在工作区里另造一份领域图。

ADR-0020 点名的另外两件不在本次，各有自己的票：`apply` 与 `from-case` 改成写活图（连同 `references/回流.md` 重画），以及 `sketch.py intake` 与 `home --empty`。落地顺序是先堵洞再搬家：中间那段时间开发侧那几条路会撞到拒绝，撞到的人从 ADR-0020 知道该往哪走。
