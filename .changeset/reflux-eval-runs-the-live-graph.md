用例「回流」真跑活图（#105，ADR-0020）：#102 把开发侧那条路的终点改成了活图、第 1 步改成 `sketch.py home --name <领域名>` 取路径，用例没跟上。种子把包内种子拷成工作区根上的 `领域图.json`，提示词直接点名「回流进 ./领域图.json」，于是第 1 步测不出，提示词与正文还打架（模型照 `references/回流.md` 会去跑 `home`，提示词却给了另一个显式目标），是一处抖动来源。`skills/` 下一个字没改，所以是 patch。

- **种子 `evals/种子/回流/回放.py` 改成跑 `home`**：不再往工作区根拷领域图，改为 `sketch.py home --name 破产` 建活图（整份 22 件、约 540 KB，多零点几秒）。取路径这一步直接用 `evals/共用/回放助手.py` 里现成的 `用活图()`，与七个路由种子同一份写法，不另写一份；包内出厂种子的路径也取它的 `出厂种子` 常量。活图家取 `LOO0NG_HOME`，跑器每次运行另建一个临时的交给两侧 harness；没设这个变量时（`--materialize`、脚本层单测）落在工作区里的 `.活图家/`，永远不碰开发者真的 `~/.loo0ng/`。
- **基线改成 `.活图基线.json`**（照种子「逐节点回流」那套）：活图的绝对路径、逐文件 sha256、模块数、节点数，外加案件图的 sha256。断言从基线里读，不硬写路径也不硬写 72。读法（`基线`、`活图目录`、`活图`、`指纹`、`节点们`）复用 `evals/共用/活图断言.py` 里那几个不认领域的函数，它的文档串跟着说清哪半边是通用的。
- **提示词不再给路径**：改成「回流进我这台机上的领域图」，取活图路径这一步由模型自己走；走岔了（写进工作区、写进包内出厂种子）断言都报红。
- **`evals/用例/回流/断言.py` 改读活图那份**，并新增一条正面的「包内出厂种子一个字节没动」：整个领域目录 22 件逐文件比（不是只比 `领域图.json`），期望值取基线里那份指纹，「活图是种子的逐字副本」这个前提由 `tests/loo0ng-domain/test_seeds.py` 的 `test_活图是包内出厂种子的一份拷贝` 钉着。这一条是本票新加的：提示词不再点名目标之后，模型自己去找「我这台机上的领域图」，找到包内种子是一种真实的走岔法，正面守一道。「没往工作区乱写」那条的期望从三样变成只有 `案件/`。
- **`tests/loo0ng-domain/test_seeds.py` 的「回流种子」跟着改**：`LOO0NG_HOME` 指进临时目录，三条建在「工作区根上有一份 `领域图.json`」上的断言改成活图那份，另加一条「活图落在临时的活图家里而不是用户主目录」。
- **种子的 `状态.md` 同改**：摊子从三样变成两样加一份活图，并写明案件那一层的 `AGENTS.md` 指针仍指着包内出厂种子（本种子不改它），模型照它去写会撞上引擎那条无条件拒。
- **`docs/agents/skills.md` 的 `evals/` 目录段跟着同步**：`共用/活图断言.py` 不再只供四个逐节点用例，`种子/` 那条先跑 `home` 的名单多一个「回流」。

**两侧各实跑绿**：Claude Code 侧三次（23 回合 118 秒、20 回合 91 秒、19 回合 87 秒），Codex 侧两次（15 回合 127 秒、14 回合 116 秒）；末一轮两侧都是在接完评审之后的这份树上跑的。#105 的风险「Codex 沙箱写不写得动活图家」实跑确认：默认 `workspace-write` 下模型在 `%TEMP%` 的活图家里写得动，不用改沙箱。回合数比 #102 之前那一版（Claude 16 回合）多出来的就是取活图路径这一步，`回合上限` 从 30 提到 40（票里只授权了跟着调 `超时秒`，但 23 回合顶着 30 没有余量，一并调了），`超时秒` 留在 480。Codex 那一跑把 uv 的缓存落成了不带点的 `uv-cache`（此前只见过 `.uv-cache`），`_is_harness_noise` 因此把 `uv-` 开头的一并当 harness 噪音忽略；这个小函数全仓七份逐字相同，七份一起改，不让其中一份走偏。

**关票触发那条路跟着补一道**：提示词不再给路径之后，手工触发时**模型自己**会跑 `sketch.py home`，而 `--materialize` 生出来的工作区不设 `LOO0NG_HOME`（回放自己兜底只管回放那几条命令，管不到 harness 里的模型），于是 `home` 解析到真的 `~/.loo0ng/`。这一条是关票触发时在 Codex 侧实测到的：一次触发就把一个合成节点写进了开发者自己那份活图。现在 `--materialize` 在活图落于工作区里的种子上多回显一行 `LOO0NG_HOME=<工作区>/.活图家` 与一句为什么要设（两条断言钉着：该回显的回显、不该回显的不多一行），`docs/agents/skills.md` 的关票触发配方两侧都加上设这个变量，那一节里「两条路手工触发时都碰不到律师真的 `~/.loo0ng/`」这句已经是假话，改写成实话。

**并入一件小的（#105 的评论）：`scripts/skill-eval.py` 加 `--model` / `--effort` 透传。** 从前跑器没有模型参数，两侧都吃各自 CLI 的默认（Codex 读 `~/.codex/config.toml`），想换模型跑只能临时改 `build_command`、跑完 `git checkout --` 还原。现在 Claude Code 侧直接加 `--model`/`--effort`，Codex 侧加 `-m` 与一条 `-c model_reasoning_effort="<档>"`；两个参数都不给时命令与从前逐字相同，这是既有跑法的兼容线（`tests/skill-eval/test_skill_eval.py` 两条断言钉着）。跑器回显第一行报出这次用的模型与档，否则跨跑比较的结果读不出是哪个模型跑的。`--materialize` 那一路照旧一个跑用例才有意义的参数都不收。命令写进 `docs/agents/skills.md`。
