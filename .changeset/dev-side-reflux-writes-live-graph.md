开发侧那两条路搬去写活图（#102，ADR-0020）：`sketch.py apply`（对通用指引手册跑雏形）与 `sketch.py from-case`（从案件图算批量候选）的终点从包内出厂种子改成开发者本机的**活图**，路径由 `sketch.py home --name <领域名>` 回显。#99 已经把引擎那条无条件拒落下去了，这两条路原先写着种子，会直接撞上它。

**零代码改动**（版号仍取 minor：变的是 skill 正文里那条路怎么走，而正文就是随包发的东西）：两条命令的形状一个字没变，换的是 `--graph` 与 `--domain` 指哪儿，正文里那几条命令示例跟着改。ADR-0020 当时就核过"`from-case` 只认 `--domain` 给的那个目录，指活图零改动"，这一版把它钉成断言。

`references/回流.md` 重画：两条路的终点统一成活图，差别只剩**粒度与时点**（律师侧一次一个节点、在确认那一刻；开发侧一批、没有时点，补历史与定制时做）。开发侧那节不再有"开分支"与"发布"两步：这条路不碰仓库里任何文件。第二双眼那一行跟着改：它守的那次写挪到了**入库**（活图那份 `领域图.json` 进仓库成为出厂种子，一次 git 提交，走分支 + PR + 隐私钩子），不在回流这一刻（ADR-0012 的 2026-09-10 附注）。末尾新增「入库」一节，把那一次写的把关写全；`intake` 本身是另一票，落地之前不写它的步骤。

**补历史那条路写明了**：律师（或开发者）把工作区 `AGENTS.md` 里「领域目录」那一行从种子换成活图之后，这个案子里此前已确认的节点**不会自动补上**，#91 定的是"不写、不再问第二次"。补它就走开发侧那条路、`--domain` 指活图；它算的是"案件图有、活图没有"的减法，已经逐节点回流进去的不会再提一遍。这一句只能落在 `references/回流.md`：`loo0ng-doit` 正文不许提 `from-case`（`tests/loo0ng-domain/test_isolation.py` 守着），`loo0ng-setup-case` 正文不许提回流（同一份测试守着）。

`loo0ng-domain` 正文三处跟着改：雏形三种来源那张表里两行开发会话的"对着哪张图"与"产出"都从种子改成活图，表下补一句这两条路的 `--graph` 指活图、路径先跑 `home` 取（雏形四步对通用指引手册那条路原先没说这个）；「领域图：谁在写哪一份」那一节把活图挪到前面写成"两侧都写它"，种子那一条改成"谁都不许在会话里写，改由入库更新"。`README.md` 同改。

守住它的是 `tests/loo0ng-domain/test_sketch.py` 新增的三条断言：跑完一次 `apply`，活图多出那几条、包内种子一个字节不变；同一份雏形冲着种子跑被引擎拒（"字节不变"才不是因为没人写它）；`from-case --domain <活图>` 走完整条路、保留原 id、整条路不碰种子。种子一律用临时假包（目录名摆成 `<…>/loo0ng-domain/assets/<领域名>`），与 `tests/loo0ng-graph/test_package_guard.py` 同一个理由：拿真包测就是拿开发者的工作树赌一次规则。

`loo0ng-setup-case` 的 `setup.py` 行为一个字没动（给了包内种子仍**只报不拒**，那是起手那一头，本票边界之外），改的只是那句已经成假话的理由：原文写"开发侧的种子回放与**回流**本来就直接对着种子跑"，回流现在不对着种子跑了；新的说法是"起手是读，写那一刻另有引擎无条件拒着"。种子「回流」的 `状态.md` 同改一处："下一次**回流**让领域图长大"改成"下一次**入库**让出厂种子长大"，并写明工作区根上那份可写副本站位的是开发者本机的活图。
