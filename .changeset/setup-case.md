新增编排 skill `loo0ng-setup-case`（user-invoked 双旗）：律师在一个空目录里打一句起手。`scripts/setup.py` 零依赖、不 import 图引擎，两个子命令。`init` 的前置是当前目录没有 `图.json`（一案一次，ADR-0007），顺序是先落图再建格，引擎拒了就一格不建：起手图三选一（`--empty` / `--full` / `--from` 转 skill "loo0ng-graph" 的引擎子进程）落下 `图.json` 与两份视图，再建六格（`收件箱/`、`材料/律师陈述/`、`指南/`、`模板/官方/`、`模板/生成/`、`文书/`），按起手图上挂到的官方模板从领域目录拷进 `模板/官方/`（缺原件只报不拒），最后照 `references/工作区AGENTS.md` 写工作区指针块 `AGENTS.md` 与一行 `@AGENTS.md` 的 `CLAUDE.md`（ADR-0009 机制 B：领域名与领域目录绝对路径、图与视图文件名、入口名、只读声明；由起手图机械推出，不加确认点）。`register` 是起手清单里「既有成品登记为已生成、来源律师」那一条的机械落地：按 `references/既有成品审查报告.md` 写一份五段固定的审查报告（每一版文书必有一份），再经引擎追加一条来源为律师的生成条目，引擎拒了就撤回报告；它只登记不确认。`SKILL.md` 写死七步的顺序与唯一那个确认点：建目录 → 起手图 → 归档（skill "loo0ng-filing"）→ `指南/` 非空则跑雏形（skill "loo0ng-domain"，只 `check` 不 `apply`）→ 回显起手清单（雏形加既有成品建议登记，合成一张）→ 律师一句话 → 写图，收尾三段同别的入口一个形状。

另交付起手两场景的种子：「空目录」（还不是工作区，`收件箱/` 里六件合成文件各对着一个归档去向加一件既有成品）与「在办中」（按真实的破产领域目录整份领域图起手、一个已确认、一个已生成未确认、两条律师陈述），并把种子「图引擎」的回放从自己写指针块改为调真的起手 CLI（另三个种子与四个用例的断言随之改）。新增用例「起手」，`tests/loo0ng-setup-case/` 三个文件跑脚本层、依赖边界与两条种子的回放。
