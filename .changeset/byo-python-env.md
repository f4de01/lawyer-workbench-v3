`loo0ng-to-docx` 的运行环境改为 agent 自备，约束的对象从「哪个解释器」换成「转换器的后端版本」（#75，ADR-0018）。起因是律师 2026-09-08 的裁定：各用户机环境各不相同，很多机器完全没有 python，写死限定等于工作台永远出不了件，而 agent 有能力自己完成初始化的配置；这是 ADR-0017「缺 Word / WPS 不得阻断出件」那条原则往上游挪了一层，理由更硬（没有渲染器只是少一层加信，没有能跑转换器的环境是一步都走不动）。`SKILL.md` 里「两个都用系统的 python；`uv run python` 不用」那句删掉，换成新的一段「跑得动转换器的环境」：怎么弄到解释器归 agent，只写四条约束（能 `import docx` 且是钉住的那个版本；装出来的东西只落在临时位置，不进案件工作区、不进 skill 目录与本仓库、不进用户全局环境；不静默；门禁本体零依赖照旧，转换器起不来时已有的 DOCX 照样检得动），另给一条 2026-09-08 在 Codex Full access 沙箱里真走通过的路（`uv python find` → `uv pip install --python <它> --target <临时目录> -r requirements.txt` → `PYTHONPATH` 指过去），并写明它只是一条路不是唯一路。受限沙箱与律师那台 mac 上能不能自备环境**没验过**，正文里如实写着未验并指向 #78、#79，不得当成已验。

顺带补上一个真洞：`python-docx 1.2.0` 此前只活在散文里（ADR-0017 与两份 changeset），仓库里没有依赖声明、没有任何机械检查，1.3 一发布自备环境的 agent 就会静默换掉「冻结转换器」的后端。现在钉子落在 `skills/loo0ng-to-docx/requirements.txt`：精确钉 `python-docx==1.2.0`（不用区间，转换器扎在 `docx.oxml` 那一层，上游对它不作 SemVer 承诺），注释里写明 python 3.9 底线的出处（律师那台 mac 是 3.9.6，底线由 #57 审定，#61 是栽在它上面的那次）与「已知可跑范围」今天只有 1.2.0 一个数。清单放在 skill 目录顶层而不是仓库根：两条安装路都只带 skill 目录，根上的清单到不了律师机（skills.sh 的拷贝器 v1.5.24 只排除 `metadata.json` 与 `.git`/`__pycache__`，插件是整目录订阅，清单两边都到得了）。

**版本对不上照跑，但必报**：转换器不因版本不符阻断出件，退出码照旧；stdout 第一行仍是「已写出 <路径>」，新增固定的第二行「出件环境：解释器 …（python x.y.z）；python-docx <实测版本>（与依赖清单钉的一致 / 依赖清单钉的是 …，这不是钉住的那个版本）」，实测版本问运行时要（`importlib.metadata`）而不是照抄清单常量。改稿指引仍只在 stderr。模型把那一行原样抄进审查报告的「生成依据」段，**恒常写、不只在对不上时写**；`references/审查报告.md` 的段落定义与两份最小样例同步更新，五段的段名与顺序没动。转换器的第三方 import 仍然只有 `docx`，读清单与报版本只用标准库。

`tests/loo0ng-to-docx/test_requirements.py` 是这颗钉子的机械守门，五条断言一条都不许 skip（ADR-0015：依赖钉不是渲染层，它红的那一刻正是它唯一有价值的时刻）：清单形状是精确钉且只此一条依赖；本机实装版本等于清单里的数；环境那一行恒常写且位置固定在第二行；拿替身包元数据跑一次验证回显里的版本取自运行时、且版本对不上时照常出件退出码为 0 并明写这不是钉住的那个；清单里的数与散文里写出它的每一处（`SKILL.md`、`references/审查报告.md` 的两份样例、`docs/agents/skills.md` 的布局表、ADR-0018）一致，散文里再多一份副本就红。`docs/agents/skills.md` 的 skill 目录布局表补上 `requirements.txt` 这一项（该表此前是封闭的五项）。门禁本体、阈值、三档结论、Markdown 最小集与表形规则一个字没动。
