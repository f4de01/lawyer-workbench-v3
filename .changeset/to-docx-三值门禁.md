版式门禁改成三值、推算层升为本体、渲染层降为机会性加信（#62，落 ADR-0017）：`scripts/gate.py` 的 `import pymupdf` 从模块顶层挪进渲染分支，门禁本体从此**零第三方依赖、且不新增任何依赖**（静态检查加 CJK 版面推算，只用 `zipfile` / `xml.etree` / `re` / `collections`），没装 PyMuPDF 也跑得动；推算器只读 DOCX 里写死的几何，不打开任何字体文件，为 `vMerge` 续格建带（不并带则四件合并单元格模板行高低估 34%～51%），正文段落按行拆页（整段挪页会每段浪费一次，长文书系统性多算页数）。`CannotRun` 里四处「无渲染后端」全部删掉，渲染层失败即跳过、只写一条披露项，无渲染时请求字体与有字没渲出来两条披露项整条消失、不报「无」；新增 `--no-render` 显式走这条跑道。结论值域改三档：推算给出 `[lo, hi]`、阈值 `T`，`T < lo` 不通过、`T >= hi` 通过、`lo <= T < hi` 需人眼，整件取最重的一档，需人眼只可能由页数、空白页、最大行高三项产生；有渲染结果时点值取代区间、这一档当场坍缩，点值落在区间外时结论以点值为准并出固定名披露项 `推算区间不含实测值`（同时进审查报告与 stderr）。退出码改为 0 通过 / 3 需人眼 / 1 不通过 / 2 门禁跑不动，落盘被拒从 1 挪到 2；`--deliver` 在通过与需人眼两档都落盘，位置相同、文件名不加装饰；重试只数不通过。结论为需人眼时门禁另出一段**须目验清单**（每行带项名、坐标、推算区间与阈值、最坏越界幅度，末尾一句「确认前请在 WPS 或 Word 里打开看这几处」），由门禁生成、模型不撰写，格式住进 `references/审查报告.md`。测试跟着分层：`tests/loo0ng-to-docx/` 每个用例现在跑无渲染与接渲染两条跑道，推算层那条在任何机器上必须全绿、不许 skip，渲染层那条缺渲染通道时 skip 并打印一行说明（ADR-0015 的口径随门禁本体改）；六行数值断言与两个魔数（45 空段、59 段）换成探针式，断言只断结论类别与项名；`test_no_backend_is_exit_2_not_a_downgrade` 反向重写成「无渲染后端照常给结论」；新增 `test_layout_estimate.py` 与三件推算回归件（行高落在 #55 没证到的 120～400 磅一段、页数正打默认的 30 页阈值、空白页在页边界收尾的一对），真值造件时 Word 与 WPS 各量一次冻进测试文件、之后零依赖，另钉住「推算全程不打开任何文件、结果可复现」；新增一件带内 fixture 钉住需人眼这一档，且 `assert_pass` 不得接受该档。对外话术从「零依赖」改口为「门禁本体零第三方依赖，且不新增任何依赖；PyMuPDF 降为可选，只在有渲染结果时才 import」，`SKILL.md`、两处 references、`README.md`、changeset 与 skill `loo0ng-doit` 的出一版一段同步。
