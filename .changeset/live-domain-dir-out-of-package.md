领域目录搬出 skill 包（#90，ADR-0019）：`~/.loo0ng/领域/<领域名>/` 是**活图**，包内 `skills/loo0ng-domain/assets/<领域名>/` 降为**出厂种子**。挡的是这条路线唯一的不可逆事故：领域图原先随包分发，律师再跑一次 `npx skills add` 升级就被整个覆盖，累计半年的图一次抹掉。`loo0ng-domain` 的雏形 CLI 多一条 `home --name <领域名>`：活图不在就从种子整份拷一份（破产那份 22 件约 540 KB，实测 0.2 秒，起手上感觉不到），已经在就一个字不动、只回显路径，回显第一行是 `活图：<绝对路径>`；活图与种子都没有的新领域它拒，那个领域从空图起手。拷贝先落临时名再改名，拷到一半断了不会留下半份被下一次当成活图。默认位置在用户主目录而不是案件根旁边：领域目录是跨案件的，不该跟着某个案件目录搬家；环境变量 `LOO0NG_HOME` 换「家」那一层，脚本层单测与 eval 跑器用它，律师那台机上不设。

`loo0ng-setup-case` 起手第 1 步先跑 `home` 取路径，再 `init --domain <活图>`；工作区 `AGENTS.md` 里「领域目录」那一行从此指活图，之后每一件 skill 都从那一行读，机制没变、没有新增确认点。`--domain` 给成包内种子时起手照做并报一句（开发侧的种子回放与回流本来就直接对着种子跑，所以只报不拒）。起手三选一不变，「整份领域图」的所指改成活图，开发者定制分发的图仍走 `--from`，两者并存不自动合并。**0.1.0 起手的工作区本版不迁移**：它们的 `AGENTS.md` 仍指着种子、仍读得到，要改用活图就手改那一行，处置写进了 `loo0ng-setup-case` 正文。`references/回流.md` 写明它描述的是开发侧那条路、写的是种子。

这一版只把领域目录搬出包，**ADR-0019 点名的另外两件 skill 不在本次**：`loo0ng-doit` 的律师侧逐节点回流、`ask-loo0ng` 定位时从活图取图，各有自己的票；`from-case` 与 `references/回流.md` 那条开发侧的路一个字没动，只写明了它写的是种子。

守住这条保证的是四条断言：**改动种子模拟一次包升级之后活图逐字不变**（本票存在的理由）、已有活图不覆盖、首次起手真的拷出三样、工作区 `AGENTS.md` 记的是活图不是种子。两侧 eval 照跑；跑器给每次运行一个临时的活图家，不往开发机的主目录里拷东西。
