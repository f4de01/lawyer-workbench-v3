# 回流是雏形机制反向跑：只回图的构成，只在开发会话做，用过一次才算通用，没有时点，第二双眼是 PR 里的 AFK 审 diff

ADR-0004 把领域图定为定义层、把"案件图反哺领域图走开发会话、剔除条目、去案件化、过第二双眼"留作独立票；ADR-0011 把"何时值得回流"从图存档票移交过来。本票定回流的对象、机制、会话、判据、时点、第二双眼、版本边界与多领域边界。用户要求：机制必须完整记录，防止日后遗忘。本 ADR 就是那份记录；`CONTEXT.md` 的「回流」词条与 `AGENTS.md` 硬边界 2 的指针都指向这里。

我们决定：

- **正式词是「回流」**：把案件图里律师长出、判为通用的模块与节点写进领域图的动作，只在开发会话发生。不用"反哺""沉淀""同步"。
- **只回图的构成**。能回流的只有律师新建的模块与节点、改过的标题、归属与顺序、空白模板属性；领域图里本来就只有这些（ADR-0004）。三样明确排除：条目永不出案件（ADR-0003）；律师陈述里的裁定不回流，通用教训走 ADR-0009 的路（经空话检验写进所属 skill 正文，不再有台账，2.0 的通用裁定台账只作素材）；案件里从过往文书剔除出来的"生成"空白模板不回流，领域目录只收官方模板原件，无官方模板的节点在领域图里空白模板属性就是"无"。
- **机制 = 雏形机制反向跑**。ADR-0007 已定"雏形机制在开发会话里对通用指引手册跑一次，产出领域图"；回流是同一机制，只是来源从指南换成一份案件图：agent 读案件图，算出"案件图有、领域图没有"的模块与节点（前方的反向减法，引擎按 id 对应），去案件化改写标题后回显候选清单，开发者一句话拍板，引擎写领域图。归 `loo0ng-domain`（雏形机制的主人），引擎仍是 `loo0ng-graph`；不新增 skill、不新增 CLI、不新增确认点以外的任何交互。
- **只在开发会话做**。当前目录是本仓库，开发者一句话给出案件工作区路径，agent 只读那份 `图.json`，写的是 `skills/loo0ng-domain/assets/` 里的领域图。律师会话里不存在"回流"这个动作，`ask-loo0ng` 不路由到它，`loo0ng-doit` 与 `loo0ng-setup-case` 正文不提它。这是硬边界 2 的正向表述：办案会话不写仓库，通用内容由开发会话誊入。
- **判为通用要两条都满足**。(a) 用过一次：该节点在真实案件里至少有一版已确认的文书；未生成、只生成未确认、不适用的节点不是候选。(b) 去掉案件事实后标题仍成立：改写成通用标题后，第二个同领域案件读得懂、用得上。模块的判据是其下至少一个节点满足 (a)。
- **没有时点，没有自动触发**。开发者维护 skill 包时做，一次把一份案件图里所有满足判据的候选批量过一遍；回流就是领域图的一次发布（changeset，minor）。信号来自派生视图：`图视图.md` 与 `图视图.json` 给每个模块与节点标 `来源: 领域图 | 案件`，"案件"来源的就是候选。来源不存进图，按 id 是否在领域图里算出（状态只算不存，ADR-0003）。这是 ADR-0011 前方 `来源: 领域图` 标记的镜像。
- **第二双眼 = PR 里的 AFK 审 diff**。回流走分支 + PR；另一个会话的 AFK 代理审 diff，专查去案件化：对照仓库外的敏感词表，再用常识识别姓名、公司名、案号、金额、日期；出报告，开发者读报告后合并。隐私钩子在 commit 时照常跑，是机械保障，不算第二双眼；回流复用同一钩子，另加审 diff 这一道。
- **案件图自足**。从领域图带入是复制，之后两边各自演化；领域图只在算前方时被读，前方是按 id 的减法，所以领域图任何改版（增节点、改标题、调顺序）只改变前方，不改案件图的任何字节。案件图不记领域图版本号。回流时保留案件节点的原 id（id 不透明），该案的前方不会多出重复项；其他在办案件会在前方多看到这个新节点，属正常。
- **只回本领域的图**。一张图恰属一个领域；把节点搬到另一领域图是开发者对那张领域图的普通编辑，不叫回流。第二个领域在本图之外。

## 考虑过的方案

- 律师每新建一个节点就触发回流：违反硬边界 2，且把未经确认的节点当候选。
- 结案时回流：结案是案件事实，图里没有，引擎无从知道。
- 案件图记领域图版本号、领域图改版时迁移案件图：案件图是自足的复制，没有任何读者需要那个版本号；迁移会改案件图，与"agent 永不改律师的图"相悖。
- 回流时给节点换新 id：该案前方会多出一个与自己重复的节点。
- 裁定也回流、恢复通用裁定台账：ADR-0004 已定图里没有要件，ADR-0009 已定行为要求进 skill 正文并过空话检验；台账是第二处存放地。
- 生成空白模板回流进领域目录：为它松动"领域目录只有三样"，而无官方模板的文书按需反推即可（2.0 裁定 3 同向）。
- 第二双眼由隐私钩子兼任：正则挡不住姓名（交叉对比 B11）。
- 独立的 `loo0ng-feedback` skill 或引擎 CLI 子命令：没有律师一句话就该被模型够到的场景，只有开发者维护时的一个动作。

## 后果

- `CONTEXT.md`：动作段新增「回流」；「派生视图」加"每个模块与节点标明来源"；「领域图」加"案件里判为通用的模块与节点经回流写入"。
- `AGENTS.md` 硬边界 2 加一句指针指向本 ADR，保证每个会话都能找到这套机制。
- ADR-0004 附注：其后果里"领域图就是剔除条目、去案件化的图存档"随 ADR-0011 失效，反哺路径由本 ADR 定。
- `loo0ng-domain` 的实现票须带"回流"场景（来源为案件图的雏形）；`loo0ng-graph` 的实现票须让两份派生视图标 `来源`，`图视图.json` 的字段随 ADR-0011 的格式版本一起定。
- 隐私钩子票里"回流是否复用同一钩子"的答案是复用，另加审 diff；该票不再被本票阻塞。
- 本 ADR 满足三条件：id 保留与来源标记进了两份 JSON 的格式，难以逆转；"只回构成、不回裁定"没有上下文会令人意外；每一条都是在两三个方案之间选的。

## 附注（2026-09-05，ADR-0014）

敏感词表不建。第二双眼「对照仓库外的敏感词表」改为靠审阅代理自己识别姓名、公司、案号、金额、日期；隐私钩子只跑正则，仍是机械保障、不算第二双眼。

## 附注（2026-09-09，ADR-0019）

本 ADR 假定回流的终点是仓库里的领域图，去案件化因此是隐私门禁、第二双眼因此是必需的。0.1.0 交付试用后这个前提变了：律师要的是自己累计的图给自己下一个案子复用，终点挪到了他本机的活图上。ADR-0019 据此改三处：

- **「只在开发会话做」被取代**，回流改为两条路：律师侧逐节点（办案会话，节点确认那一刻，写本机活图），开发侧批量（补历史与定制分发，写仓库里的出厂种子）。随之失效的还有本文"律师会话里不存在回流这个动作，`ask-loo0ng` 不路由到它，`loo0ng-doit` 与 `loo0ng-setup-case` 正文不提它"这一句。
- **判据 (b) 在律师侧降级**：去案件化在活图那条路上不是隐私门禁（活图不进仓库，硬边界 1 管不到），只是"别让 A 案的名字出现在 B 案的图里"的可用性要求。判据 (a)「至少一版已确认」不动，而且正是它把时点定在了确认那一刻。
- **第二双眼只守开发侧那条路**，律师侧没有这一道。

本文其余各条（只回构成、案件图自足、只回本领域、保留原 id、没有自动触发）一条不动。`from-case` 不废，降为补历史与开发侧维护的入口。
