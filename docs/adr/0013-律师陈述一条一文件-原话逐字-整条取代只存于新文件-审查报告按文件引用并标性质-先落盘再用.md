# 律师陈述一条一文件、原话逐字，整条取代只存于新文件，审查报告按文件引用并标性质，对话里的事实先落盘再用

ADR-0002 把裁定台账并进律师陈述、废掉取值台账；ADR-0007 把位置定在 `材料/律师陈述/`；ADR-0008 定陈述由律师一句话触发、无入口无确认、生成缺事实时律师答的一句也走这条路；ADR-0009 把落档归 `loo0ng-filing`。2.0 的陈述 schema（`knowledge/规范/案件目录规范.md`）里「改口不改文件，追加新陈述，由 agent 在取值台账登记新值取代旧值」这条机制随取值台账一起没了，取代要另定；「回应待决」指向的待决标记在 3.0 也不存在。本 ADR 定陈述文件的粒度、命名、头部、正文、三档语义、取代机制、审查报告引用方式、与归档的边界。

我们决定：

- **一条陈述一个文件，落盘后只读。** 追加式单文件违反 ADR-0002「agent 永不写入案件工作区里已存在的文件」；一文件一条使「按文件引用 = 按条引用」与「改口 = 新文件、旧文件字节不动」都成立。
- **文件名 `YYYYMMDD-HHMMSS-<标题>.md`**，时间在前使目录顺序即录入顺序，到秒避免撞名；标题由 agent 从律师那句话拟（不超 20 字、不含案件人名、无标点），律师不起题。录入时间取落档时刻，事件本身何时发生写在正文。
- **头部为 front matter，六个字段，引擎按行切 `键: 值`，不用 PyYAML**（ADR-0003 本机无 PyYAML）：`性质`（直接陈述 | 转述 | 裁定）、`转述来源`（仅转述必填）、`录入时间`、`节点`（可空可多，用图内唯一标题）、`回应`（可空；答审查报告待裁定项时指向那份审查报告）、`取代`（可空；旧陈述文件名）。2.0 的 `录入通道` 恒为对话、是常量不存；`回应待决` 改为 `回应`。
- **正文以原话为主、整理为辅。** `## 原话` 段逐字记律师那句，agent 不润色不补词，与 ADR-0010 留痕规则 (a) 同一原则；一句话带多个值时 agent 在 `## 整理` 段附「项目 | 值」表并标明是 agent 整理，单值陈述不写整理段。`性质: 裁定` 时正文固定 `## 问题` `## 裁定` 两段，头部不加字段；2.0 通用裁定台账六列里裁定人恒为律师、适用范围恒为本案、日期已在头部，全是常量或重复。
- **三档语义**：直接陈述 = 律师本人是权威来源的事实；转述 = 律师转录他人或他处、来源强度低一档；裁定 = 律师对本案某个问题的选择，不是事实。确认与不适用不是陈述，是图里的条目。案件级裁定回流到通用层不在本 ADR（ADR-0012 只回图的构成）。
- **取代关系只存在新文件里，整条取代。** 新陈述头部 `取代: <旧文件名>`，旧文件一字不动，「被取代」由新文件推出、不存进旧文件，与 ADR-0003「状态只算不存」同构；现行陈述 = 未被任何文件指为取代目标的那些。只改一个值时也整条取代：agent 把旧陈述其余现行值抄进新陈述的整理段，原话段仍只是律师新说的那句。落档脚本校验取代目标存在于同目录。
- **审查报告按文件相对路径引用陈述，附性质标签与所引的值**：`[律师陈述·转述] 材料/律师陈述/<文件名>：<项目> <值>`；多值陈述再加「之『项目』」指到整理表的行，不引行号。审查报告须区分三档来源强度；转述值与书面材料冲突不停下来问，列进「待律师裁定」（ADR-0008），律师答一句成一条 `性质: 裁定`、`回应:` 指向该报告的陈述后重出。只引现行陈述；报告面向那一版文书，引用后来被取代的陈述不算错。
- **不在盘上的事实不是材料。** 律师在对话里口头给的事实，agent 先落成陈述、回显一行，再据此生成；理由是审查报告的依据必须可引、下一回合是新对话看不到上一对话（ADR-0008）、材料只能整读文件（ADR-0007）。落档瞬时完成，不是确认点。这条写进 `loo0ng-doit` 与 `loo0ng-filing` 正文，不进 `AGENTS.md`（ADR-0009）。
- **落档是 `loo0ng-filing` 里独立的第二个零依赖脚本，与归档脚本互不 import；归档永不写入 `材料/律师陈述/`。** 归档只搬不写（ADR-0007），落档是新建内容由 agent 给出的文件，动作性质相反。脚本零语义：拟文件名、拒绝覆盖、校验转述必填来源、校验取代目标存在，其余判断归模型。律师自己写的 `.md` 拷进收件箱经归档只是普通材料，没有性质；要成为陈述就说一句。
- **不设「现行陈述清单」派生视图。** 目录按时间排、文件名自述、取代关系读头部即得，agent 生成时本来就整读 `材料/`；陈述不在图里，也不进 `图视图.md`（派生视图不承载图里没有的事实）。

## 考虑过的方案

- 一案一个追加式 `律师陈述.md`：违反「已存在文件永不写」的保护形态。
- 旧陈述改名或移到 `已取代/`：动了材料的文件名与路径（ADR-0007）。
- 不做显式取代标记、同一主题以时间最晚为准靠 agent 判断：提示词级保护，legal-skills 的教训是长会话里不可靠（ADR-0002）。
- 部分取代（只取代一条里的一个值）：审查报告引用时说不清「这条哪一半还算数」。
- 陈述落档做成归档脚本的子命令：给只搬不写的脚本开一个写内容的口子。
- 正文只存 agent 整理后的结构化版本：律师原话不可复核；2.0 补值表格式依赖的替换清单与待决标记已不存在。
- 每次落档重算一份现行陈述清单：解决的是尚未发生的事故。

## 后果

- `CONTEXT.md`「律师陈述」条改写，「审查报告」「归档」条各加一句。
- `loo0ng-filing` 持两个 CLI：归档搬运、陈述落档；`loo0ng-to-docx` 的审查报告格式收下引用格式与三档来源强度。
- 期限是否进图的前提（主循环与陈述形态）已齐，转为独立票。
- 出现一次「陈述多到 agent 读错现行值」的真实事故再议派生清单。
