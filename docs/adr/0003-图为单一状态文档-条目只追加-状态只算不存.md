# 图为单一 JSON 状态文档，条目只追加，状态只算不存

ADR-0002 定下"单一文件 + 写入引擎 + 代码级拒写 + 派生视图"的前提，留下了文件形态、身份、排序、状态、写权与并发六个选择。我们决定：

- **状态文档，不是事件日志**。`图.json` 就是图的当前形态：顶层只有 `领域` 与 `模块` 两项，模块内嵌节点，节点内嵌自己的条目列表。不做只追加的事件日志，图小，不需要回放式伸缩。
- **JSON，不是 YAML**。写入引擎必须在 Claude Code 与 Codex 两边零依赖直接跑；本机没有 PyYAML，PyYAML 又会把日期字面量自动转型、整文件 dump 丢注释。律师从不直接读这个文件，可读性只对引擎与 agent 有意义。
- **不透明 id + 图内唯一标题**做行身份；**数组顺序即顺序**，不设序号字段，不设跨模块节点序。
- **条目只追加**。引擎没有改条目、删条目的操作；来源由动作类型推出，不留 `--actor` 给 agent 选。"agent 永不改律师条目"由此从合并规则退化为"谁都改不了任何条目"。
- **状态只算不存**。节点状态严格可由条目推出（无条目=未生成；末条为生成=已生成、确认=已确认、不适用=终态），文件里不存 `状态` 字段，引擎与派生视图输出算好的值。
- **没有删除**。节点与模块只能新增、改标题、排序、改空白模板属性、跨模块移动；不要了就不适用，模块级不适用等于其下所有节点不适用，误加的也走不适用。
- **严格惰性**。只有动作指向图里没有的节点时才按模块定义创建该节点，其模块不存在则一并创建，不带入同模块其他节点；初始化产出空图；路由从模块定义回答"接下来做什么"，不写图。
- **不设锁**。每个节点的文书生成都在新对话里跑，一个案件同一时刻只有一个写者；写入只做临时文件 + `os.replace`（本机中文路径已验证原子）。出现双开写坏文件的事故之后再加锁。
- **律师手改文件不受支持**。所有写入经唯一的写入引擎；引擎发现文件不合校验即拒写并提示，不猜。

## 考虑过的方案

- 只追加事件日志（JSONL）：天然满足条目不可变，但路由、可视化每次都要回放，而条目不可变已由引擎无改删操作保证。
- YAML 状态文档：对模型更好读，但要引入依赖、要处理类型转型；收益落在律师不读的文件上。
- 存显式 `状态` 字段并校验一致：`cat` 时一眼可见，但同一事实存两处，违反 ADR-0002 的不冗余原则。
- 首次触及模块时带入定义里的全部节点：派生视图能看到"前方"，但与"由节点补全模块"相悖，且会制造大量律师须逐个宣告不适用的未生成节点。
- 锁文件 + 修订号防丢失更新：解决的是不存在的并发场景。

## 后果

- 图的顶层只有 `领域` 与 `模块`；案件名、案号、当事人等案件元数据不进图。要件、期限、并行依赖不进图：要件属于模块定义，期限暂留迷雾。
- 生成条目携带文书与审查报告的相对路径（相对工作区根）；文书版本由生成条目序列推出，不另存版本表。
- 派生视图是一份 Markdown（`图视图.md`），每次写入后覆盖式重生成；是否同时出 HTML 由图存档票定。
- 写入引擎由唯一一个参考 skill 拥有，编排 skill 通过它写，路由只读。
- 图存档的格式可以直接是图文件本身的保存版本，图存档票在此前提上定"趋近完整"的判据与存档时点。
