# 回流有两条路：律师侧逐节点在确认时做，领域图搬出包外成为活图，包内那份降为出厂种子

ADR-0012 把回流定成"只在开发会话做、开发者批量过一遍、第二双眼审 diff"，前提是**回流的终点是本仓库里的领域图**，所以去案件化是隐私门禁、第二双眼是必需的。0.1.0 交付试用之后这个前提变了：律师要的不是把图交回开发侧，而是**自己这一个个案子累计出来的图，下一个案子能接着用**。终点从仓库挪到了律师自己的机器上，隐私门禁那一整套就不再是这条路上的东西。

同时这条路改变了泛化的入场费。原来每个新领域要先找到指引手册、跑一次雏形长出领域图（#30 对破产做的那一套）；空图累计这条路把入场费降到零，新领域直接从空图起手，图靠办案长出来。

我们决定：

- **回流仍是一个词，两条路。** 方向与对象不变（案件图的构成写进领域图），变的是会话、时点与审查强度：**律师侧逐节点**是默认路，在办案会话里、节点确认那一刻做，写的是律师本机的活图；**开发侧批量**保留，做两件事，补这套机制上线前已确认的历史节点，以及开发者定制领域图后分发。不新造"累计""沉淀""同步"这些词，`CONTEXT.md` 的「回流」词条改成两条路，不新增词条。

- **时点就是节点确认那一刻。** ADR-0012 判"通用"的第一条判据是"该节点在真实案件里至少有一版已确认的文书"，这条判据在律师确认的那一刻天然成立，不必另找信号，也不必等结案（结案是案件事实，图里没有，ADR-0012 已拒过这个时点）。

- **只对领域图里没有的节点问。** 判断哪些节点缺，用的是前方的反向减法，引擎按 id 对应，已有的机制。领域图里已有的节点一个字不问。**这条自带衰减**：头几个案子问得多，图越完整问得越少，一个领域走熟之后趋近于零，只有真正的新节点才会再问。律师侧明确接受这个代价（2026-09-09）。

- **归属默认继承案件图的模块，标题由 agent 提去案件化的默认值。** 律师确认文书之后，agent 回显这个节点的归属提案：模块取它在案件图里所在的那个，标题取去掉当事人、案号、金额、日期之后仍成立的写法（`from-case` 的标题改写已经在做这件事）。律师一句话拍板，未拍板不写领域图（与雏形机制同一条规矩）。改归属、改标题、跨模块移动、新建或改名模块，用的都是现成的引擎能力，不新增 CLI。

- **去案件化在这条路上是可用性问题，不是隐私门禁。** 活图不进仓库，硬边界 1 管不到它；要防的只是"A 案当事人的名字出现在 B 案的图里"。所以**律师侧这条路没有第二双眼**，第二双眼仍然守着开发侧那条（进仓库的才需要，ADR-0012 那一条不动）。

- **律师侧新增的节点不给时限句。** 时限只住领域图（ADR-0016），但在确认那一刻追问一句法定期限，与"只问归属"这一个问题的克制相悖，而时限本来就允许整个缺省。缺了的由开发者维护领域图时补。

- **领域目录搬出 skill 包：`~/.loo0ng/领域/<领域名>/` 是活图，包内 `skills/loo0ng-domain/assets/<领域名>/` 降为出厂种子。** 首次起手时活图位置没有这个领域，就从种子拷一份，之后只认活图；skill 包升级只换种子，一个字碰不到活图。放用户主目录而不是案件根旁边，是因为领域目录是跨案件的，不该挂在某一个案件根下，也不该跟着案件目录搬家。工作区 `AGENTS.md` 里"领域目录绝对路径"这一项照旧，只是现在指向活图。

- **开发者定制分发的领域图与活图并存，起手时选，不自动合并。** 复用现成的起手图三选一（ADR-0004）：「整份领域图」指向活图，开发者分发的那份走 `init --from`。"这个案子用哪张图起手"本来就是起手时该做的选择，不需要第二套机制。

- **硬边界 2 不动，ADR-0012 的会话那一条被取代。** 活图在 skill 包之外，不是本仓库，律师会话写它不破"办案会话对本仓库只读"。被取代的是 ADR-0012 里"律师会话里不存在回流这个动作，`ask-loo0ng` 不路由到它，`loo0ng-doit` 与 `loo0ng-setup-case` 正文不提它"这一句。

## 考虑过的方案

- **把归属那一问做成静默默认、不问律师**：能省掉全部交互，但律师侧明确要这一问，理由是模块归属的裁判权本来就归他（ADR-0004），而 agent 猜错一次就会在领域图里留下一个错分类的节点，越用越难改。
- **每个节点都问，不看领域图里有没有**：交互量不衰减，一个走熟的领域每个案子仍要问几十次，正是 2.0 "反复确认"的形态（handoff §2.1）。
- **不问归属，回流时把节点一律挂在一个"未归类"模块下，事后整理**：把一次一句话的裁定，换成日后一次大扫除，而且中间所有派生视图都带着那个假模块。
- **分发的领域图按 id 合并进活图，同 id 以律师的为准**：律师不丢东西，但要新写合并逻辑与冲突规则，且合过一次就回不去；起手三选一已经把这个选择摆在正确的时点上。
- **分发即覆盖，活图另存备份**：把"累计被抹掉"这个事故换个形式重演一遍。
- **活图放案件根旁边**：律师自己看得见、备份方便，但案件根一搬就得跟着搬，而领域目录是跨案件的。
- **活图位置起手时问律师**：最灵活，但 ADR-0008 把起手的确认点数死为最多一个（起手清单），为一个几乎不变的路径再加一问不值。
- **律师侧那条路另起一个词（累计 / 沉淀）**：两个动作的会话、时点、审查强度确实不同，分开叫不容易搞混；但方向与对象完全相同，`CONTEXT.md` 是权威词汇表，多一个词的代价长期大于分辨的收益。ADR-0012 已经明确拒过"沉淀""反哺""同步"作为这个动作的名字。
- **律师侧也过第二双眼**：第二双眼是为进仓库设的，活图不进仓库；在办案会话里再拉一个 AFK 代理审 diff，成本和延迟都落在律师的回合里。
- **确认时顺带问时限**：把一个问题变成两个，而时限允许缺省，破产以外的领域可以整个没有。

## 后果

- **ADR-0012 部分取代**：会话那一条改为两条路（律师侧逐节点、开发侧批量补历史与分发）；判据 (a)"至少一版已确认"不动，(b)"去案件化后标题仍成立"在律师侧降为可用性要求；第二双眼那一条只对开发侧那条路有效。ADR-0012 加同日附注。
- **ADR-0004 扩宽**：模块构成"律师在案件图上、开发者在领域图上"改为律师在这两张图上都可裁定，开发者维护出厂种子。加同日附注。
- **ADR-0008 的确认点清单加一条**：每份文书确认之后，若该节点领域图里没有，多一次归属拍板。它是有条件的，且随领域图变完整而衰减到零。加同日附注。
- **`CONTEXT.md` 三个词条改**：「回流」改成两条路；「领域目录」区分活图与出厂种子；「领域图」写明律师侧也写。
- **`AGENTS.md`**：硬边界 2 补一句活图在包外、不受只读约束；结构不变量第 5 条「领域目录三样」仍成立，但要写明约束的是包内种子。
- **四件 skill 要改**：`loo0ng-setup-case`（首次起手拷种子、三选一里「整份领域图」指活图）、`loo0ng-domain`（活图路径解析、逐节点回流的回显与写入）、`loo0ng-doit`（确认之后那一次归属拍板）、`ask-loo0ng`（定位时读的领域图从活图取）。
- **`from-case` 不废**，降为补历史与开发侧维护的入口。
- **一条代价照实记**：新领域从空图起手时前方是空的（前方 = 领域图有、案件图没有的减法），头几个案子里 `ask-loo0ng` 回答"接下来做什么"拿不出前方，只剩当前状态那一半。这是空图累计换来的低入场费的账单。
- 本 ADR 满足三条件：活图位置与"包内是种子"这个分层一旦落地，工作区里的路径与升级流程都建在它上面，难以逆转；"回流有两条路、律师侧没有第二双眼"没有上下文会让人以为隐私边界松了；每一条都在两三个方案之间选过。

## 附注（2026-09-10，ADR-0020）

本文"**开发侧批量**保留……写的是仓库里的出厂种子"改为写开发者本机的活图：领域图的构建两侧同一条路，开发者要定制或维护一个领域图，也是办一遍、逐节点回流进自己那份活图。包内种子谁都不许在会话里写，引擎无条件拒（判定在 `Engine.commit()`，只拦写不拦读），种子改由**入库**更新。

起因是本文与 #90「0.1.0 工作区不迁移」合起来留的一个洞：那些工作区的指针块指着包内种子，在它们上面走一遍逐节点回流，写的就是随包分发的那份文件，下一次升级整个换掉——而律师那台机器上没有 git、没有隐私钩子，丢失是静默的。

本文其余各条不动：时点仍是节点确认那一刻，只对领域图里没有的节点问，归属与标题两个默认值，未拍板不写，律师侧不给时限句、没有第二双眼，活图位置与"包内是出厂种子"这个分层，起手三选一不自动合并。
