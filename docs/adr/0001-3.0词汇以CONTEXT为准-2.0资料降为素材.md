# 3.0 词汇以 CONTEXT.md 为准，2.0 定义与裁定降为素材

`knowledge/` 保留了 2.0 的资料：流程模型把"模块"定义为固定 12 个章节、"节点"定义为小节，裁定台账有 13 条裁定要求全部下游引用遵守。3.0 的设计（节点 = 一份文书、模块可增删的惰性集合、图为案件流程的状态全集）脱离了案件材料包本身，也脱离了 2.0 的大部分裁定。我们决定：3.0 的词汇与规则从 `CONTEXT.md` 和 3.0 自己的 ADR 重新定义；`knowledge/` 下 2.0 的流程模型、模板、文书卡、裁定台账只作为**内容素材**读取（用于产出模块与节点），其中的词汇定义、机制限制与裁定不约束 3.0 的设计。唯一延续的约束是 `AGENTS.md` 的两条硬边界。

## 考虑过的方案

- 沿用 2.0 定义，把 3.0 设计翻译成旧词：85 处"模块"、196 处"节点"在旧文件里的含义与新设计相反，翻译后每个 skill 都要带一份对照表，路由和 agent 读旧文件时会读错。
- 改写 `knowledge/` 使其符合新词：素材量大，且素材的价值在于内容和出处，改写词汇不增加价值，反而丢失与指引、手册的对应关系。

## 后果

- 读取 `knowledge/` 时，遇到"模块""节点"要按素材原义理解，再映射到 3.0 词汇；skill 与 issue 中一律使用 `CONTEXT.md` 的词。
- 2.0 的事故记录（裁定台账 #8–#11 等）仍可作为验收项引用，但不作为规则引用。
