# 隐私守门只做零维护的正则钩子：不建敏感词表、不做 CI，main 上守领域图与 knowledge 两处路径，只约束开发者

硬边界 1（案件材料永不入本仓库）原文提到「敏感词表只存在于仓库外」，ADR-0012 的第二双眼也写着「对照仓库外的敏感词表」，而这张表从未存在，也没有任何 skill 或流程维护它。legal-skills 的 J7 是 pre-commit 正则钩子 + 本地黑名单，它自己却被没人维护的那一环污染过（交叉对比 B11）。本 ADR 先判必要性，再定钩子的落点、检查内容、扫描范围、路径守门与实现形态。

先厘清一处误解：敏感词表与「跨对话后模型记错前阶段材料」无关。那个问题已由材料整读（ADR-0008）、律师陈述先落盘再用（ADR-0013）、条目只增状态只算（ADR-0003）解决；模型不靠记忆，靠重读盘上的东西。词表只服务硬边界 1。

我们决定：

- **钩子不是功能件，是兜底；只引 J7 里零维护的一半。** 案件内容进仓库的路只有三条：办案会话（硬边界 2 已结构性堵死）、开发会话的回流（ADR-0012 已配 PR + AFK 审 diff）、开发会话写 issue / commit message / ADR 时顺手引用。钩子只为后两条兜底。
- **不建敏感词表。** 硬边界 1 与 ADR-0012 里的「敏感词表」字样删去；第二双眼靠审阅代理自己识别姓名、公司、案号、金额、日期。词表是 J7 里唯一要人持续维护的部分，姓名又恰是 LLM 审 diff 比正则更擅长的东西。
- **落点是本地 pre-commit + commit-msg 两只钩子，不做 CI。** CI 在 push 之后才跑，内容那时已经在 GitHub 上，只能报警不能阻止。「钩子没装上」由 `scripts/link-skills.ps1` 顺手设 `core.hooksPath .githooks` 解决，ADR-0009 已要求改后必跑它。
- **正则拦五类**：法院案号（含「破」字号）、`D:\Claude\Data\Cases\` 根之下任何一段路径（根本身放行，`AGENTS.md` 里就有）、11 位手机号、18 位身份证、统一社会信用代码。不拦座机：7 到 8 位数字误伤面大。
- **扫三处，二进制分两类。** 扫暂存 diff 的新增行、暂存文件的文件名、commit message。`.docx/.xlsx/.pptx` 用标准库 `zipfile` 拆开扫 XML（官方模板可能附示例案号）；其他二进制放行但在输出里点名。照版式门禁「不通过项 / 披露项」的分法：能客观判的拦，判不了的披露给人看。另带全仓扫描模式，装钩子那天跑一次做基线。
- **main 上守两处路径**：在 `main` 直接提交触及领域图文件或 `knowledge/` 即拒绝，须走分支 + PR + AFK 审 diff。这两处正是「案件内容经开发者的手进仓库」的全部来路：回流唯一写的是领域图文件，`knowledge/` 誊入是硬边界 2 点名的另一处。不守整个领域目录：官方模板原件与通用指引手册按定义不含案件内容，且领域目录初建时会反复改。
- **issue 正文**：检查器支持从 stdin 读文本，`docs/agents/issue-tracker.md` 加一句「写 issue 正文前先喂检查器」。不写 `gh` 包装脚本。
- **实现形态**：检查器是 `scripts/privacy-check.py`（Python 标准库、零依赖，同 ADR-0013 的落档脚本）；`.githooks/pre-commit` 与 `.githooks/commit-msg` 是两行 shim；命中时输出文件、行号、类别，不给任何绕过提示，修法只有改内容。ADR-0009 留的「隐私钩子 skill 槽」关闭：它没有律师一句话能够到的场景（`invocation.md`「could the model usefully reach for this autonomously?」），是开发者仓库的守门工具，与 Matt 的 `scripts/link-skills.sh` 同一层。不用 PowerShell：钩子由 Git 的 sh 起，且 PS 5.1 有 BOM 坑。
- **只约束开发者。** 律师在本地用 agent 办案，没有提交动作、不连 GitHub；钩子随仓库走、不随 skill 包分发，`loo0ng-setup-case` 不把它写进工作区。唯一用到这套限制的人是开发者。

## 考虑过的方案

- 完整移植 J7（正则 + 词表，词表每个新案手工维护）：词表是没人维护的那一环，legal-skills 自身即反例。
- 不做任何钩子：设计在功能上自洽，也成立；代价是失去案号与案件目录路径这两样最可能在回流标题、commit message 里漏出的东西的零成本拦截。
- CI 跑正则半作兜底：push 后才跑，为时已晚。
- 守整个领域目录：逼着领域目录初建时每次小改都开 PR。
- 做成 `loo0ng-*` 参考 skill：没有模型该自行够到它的场景。
- 拦未知二进制：图片等无法扫的文件会被误拦；改为披露。
- 拦座机：误伤面大。

## 后果

- `CONTEXT.md` 新增「第二双眼」词条；「隐私钩子」是实现细节，不进词汇表。
- `AGENTS.md` 硬边界 1 删去「敏感词表」，加一句指向本 ADR 的指针。
- ADR-0009 附注：隐私钩子的 skill 槽关闭。ADR-0012 附注：第二双眼不再对照词表。
- `docs/agents/issue-tracker.md` 加一句检查器指引。
- 钩子的实现随 `/to-spec` 之后的建仓工作落地：`scripts/privacy-check.py`、`.githooks/` 两只 shim、`link-skills.ps1` 加 hooksPath 一行、全仓基线扫一次。
- 本 ADR 满足三条件：不建词表、不做 CI、只守两处路径，没有上下文都会让人奇怪；每条都在两三个方案间选过；钩子一旦装上再改守门范围会影响已有分支流程。
