# 门禁本体 = 零依赖推算层，渲染降为机会性加信；结论三档，需人眼件落盘

ADR-0006 把版式门禁定义为「真实渲染而非对文件结构的猜测」，并在后果里留了一句预言：「假设律师使用 Codex 的机器与开发机相同、有 Word；若不同机，『无渲染后端』会是常态，门禁的降级策略须重议。」那句预言中了，本 ADR 就是那次重议。

重议的直接起因是实测出来的环境矩阵（地图 [#54](https://github.com/f4de01/lawyer-workbench-v3/issues/54)）：

| 环境 | 渲染通道 | 依据 |
| --- | --- | --- |
| mac + WPS（**主力**） | **无** | #41：wpscli 是纯 PDF 工具箱，WPS 的 AppleScript 没有文档对象模型 |
| mac + Word | API 有，**无人值守不成立** | #56：TCC 授权非 MDM 无法预授权、Office 沙箱按文件授权、微软原文写 "cannot run unattended"、无 headless |
| Windows + WPS | 有：32 位宿主里 `KWPS.Application` | #56、#60 |
| Windows + Word | Word COM | ADR-0006 原路径 |

律师办案那一格**恒定没有渲染器**。2026-09-07 律师就此当场裁定：**缺 Word / WPS / 其他软件，不得阻断文书生成**。这一句与 ADR-0006 明文「没有渲染后端时明确报错、拒绝出件，不静默降级为静态检查」正面冲突，律师这句赢。

五张决策票把重议所需的事实全部量了出来：**推算能替代渲染**（[#55](https://github.com/f4de01/lawyer-workbench-v3/issues/55)：纯标准库推算器在 25 件样本上页数 / 空白页 / 最大行高全部 25/25 落在推算区间内、零翻转，且推算全程不碰字体文件，四种环境上给出的数完全相同）；**渲染器这把「尺子」没有价值**（[#60](https://github.com/f4de01/lawyer-workbench-v3/issues/60)：Word 与 WPS 逐件对照页数 25/25 相同、最大行高绝对差 ≤0.1 磅，且**每一件的两引擎间距都窄于推算区间宽度**：它量的是 DOCX 里本来就写死的几何，方差住在字体替换那一侧，不在渲染引擎这一侧）；**依赖与版本底线压得下去**（[#57](https://github.com/f4de01/lawyer-workbench-v3/issues/57)）；**fixture 一件不用重建**（[#59](https://github.com/f4de01/lawyer-workbench-v3/issues/59)）；**结论值域改三档**（[#58](https://github.com/f4de01/lawyer-workbench-v3/issues/58)）。

我们决定：

- **门禁本体 = 零依赖计算层。** 静态检查（读 zip 与 XML）加 CJK 版面推算（同样只用 `zipfile` / `xml.etree` / `re` / `collections`），**零第三方依赖，且不新增任何依赖**。它在四种环境上给出相同的数，因为它不打开任何字体文件。推算必须为 `vMerge` 续格建模：续格与上一行之间没有横线、渲染成一条双高的带，不并带则四件合并单元格模板行高低估 34%～51%，方向危险（#55）。

- **渲染层降为机会性加信。** 有渲染通道时用它的点值**取代**三项渲染相关判据的推算区间，收紧不确定；没有则**跳过，只写一条披露项**。渲染失败不再是错误：`CannotRun` 里「无渲染后端」整条取消：主力环境上没有渲染器是**正常路径**。PyMuPDF 随之降为可选，只在有渲染结果时才 import；这与渲染层机会性化是同一次改动，四环境矩阵里没有任何一格是「有 PyMuPDF、没有渲染通道、PyMuPDF 还有用」。

- **结论三档：通过 / 需人眼 / 不通过。** 判定式：推算器给出 `[lo, hi]`、阈值 `T`，`T < lo` → 该项不通过，`T >= hi` → 该项通过，`lo <= T < hi` → 该项**需人眼**；整件取最重的一档（不通过 > 需人眼 > 通过）。**不加缓冲带**。**第三档只可能由页数、空白页、最大行高三项产生**；其余七项静态判据（占位残留、模板原文残留、页脚 PAGE 域、表格接 sectPr、docProps 元数据、表宽超页、空单元格）读 XML 得点值、没有区间，**恒为二值**。需人眼永远指向一个几何量，不指向结构问题。

- **渲染器在场时这一档当场坍缩成二值。** 点值落在推算区间外时，**结论以点值为准**（真实渲染永远比推算权威），另出固定名披露项 `推算区间不含实测值`（带项名、实测点值、推算区间），**同时写进审查报告与 stderr**；它的唯一读者是开发者，是 ADR-0006「一次事故 → 一条规则 + 一对 fixture」那条进入路径的触发器。

- **fail-closed 重述：守的不是「落盘」这道门，是「不把测出来的事故当合格件交出去」。** 两条：**测出来的事故**（七项静态项命中，或某项的整个区间越过阈值）→ 永不落盘，ADR-0006 那条一个字不改；**测不准**（阈值落在区间内）→ **落盘**，位置与通过件相同、文件名不加任何装饰，但结论字段是「需人眼」。

  落盘不是权衡出来的，是推出来的：**区间存在的唯一原因就是这台机器上没有渲染器**，所以「需人眼件不落盘」= 缺渲染器时这件文书出不来 = 缺渲染器阻断了文书生成，正是律师当场否掉的那件事。而口子并不存在，因为本项目里**落盘 ≠ 确认**：`CONTEXT.md` 写死「确认只能由律师发起，agent 永不代做」，真正保护律师的门是确认。需人眼这一档的作用，是把律师本来就要做的那次确认，从「泛泛读一遍报告」变成「去看这三个坐标」。

- **三值不是静默降级。** 写死这一句：*降级是「能力缺失时假装做了」；三值是「能力缺失时如实报出不确定的宽度，且该能力一在场，不确定当场归零」。静默降级的反面不是「更严」，是不确定性可见、带坐标、且随能力到位而消失。* 它的可执行部分在退出码里：**零只有一个，任何非零都不许被当成通过用**。

- **退出码**：`0` 通过（有 `--deliver` 则已落盘）／`1` 不通过（不落盘）／`3` 需人眼（有 `--deliver` 则已落盘）／`2` 门禁跑不动：文书或模板打不开、推算层自身抛异常、用法错误、落盘被拒（目标已存在）。落盘被拒从 1 挪到 2，因为它不是「文书不合格」。

- **重试只数不通过。** 需人眼不触发重试、直接落盘交人；不通过仍是「agent 改 Markdown 重转重检至多 2 次」。一件同时有两档时结论取不通过、重试针对不通过项；重试后不通过项清了、需人眼还在，按需人眼落盘。带内重试会**为了让尺子好读而改文书正文**，是净损失。

- **模型对结论没有写权。** 原文引用 ADR-0006 并注明**不动**：「验收由门禁跑 fixture 得出，**不采信生成侧自报通过**」；「仍不过就报生成失败，把门禁结果原文交给律师，**不交出不合格件**」。模型只做两件事：把不确定项翻译成人话写进审查报告；在写 Markdown 那一步就把过长的标记改短（**预防，不是兜底**）。第三档不重试，使预防成为唯一的杠杆。

- **须目验清单是结构，不是散文。** 结论为需人眼时，审查报告**第一段**是固定格式的须目验清单：每行一项，带项名、坐标、推算区间、最坏越界幅度，末尾一句「确认前请在 WPS 或 Word 里打开看这几处」。由门禁生成，**不由模型自由撰写**；格式住进 `loo0ng-to-docx` 的 references。

- **图不记这一档。** 生成条目不加键，`ACTIONS` 不动，不新增第四种节点状态；结论只住审查报告一处，生成条目已经指着那份报告。

- **阈值是单一常量，不按后端分组。** 「每后端一行数字」的退路保留在纸面上，触发条件写死成两句可判定的话：(1) 同一件在两个渲染器上落在阈值两侧（换后端会翻转结论），哪怕只有一件；(2) 或推算区间容纳不下两个渲染器的实测值。**#60 实测两条都不满足**，退路不启用，举证责任在提议分组的一方。

- **fixture 的角色是一致性测试，不是保真基准。** 现行这把尺子从第一天起就是几何代理（开发机无方正字体、Word 一直在用替换字体量几何，而律师交出去的那张纸是从 WPS 打印的）。新角色：在任一可用后端上（**含没有后端**）故障件必拦、正常件必过；**断言只断结论类别与项名，不断数值**；阈值当参数注入。**跨环境一致不作验收项**（不押在拿不到的 Mac 上），换成钉推算器的构造属性：**不打开任何字体文件、结果可复现**。并立一条规矩：**结论值域每多一档，fixture 必多一件把那一档钉住，且 `assert_pass` 不得接受该档。**

- **依赖与版本底线。** 对外话术从「零依赖」改口为**「门禁本体零第三方依赖，且不新增任何依赖；PyMuPDF 降为可选」**：skill 包整体不是零依赖，转换器的 `python-docx 1.2.0` 拉进 `lxml`（编译扩展）与 `typing_extensions`。**python 底线 = 3.9**，由 `python-docx 1.2.0` 的 `Requires-Python >=3.9` 顶住，正好压在律师那台 mac 的 3.9.6 上、一格余量都没有。

- **ADR-0015「缺 Word 即 fail 不 skip」改口径。** 降级的定义随门禁本体走：本体已是零依赖推算层，所以**推算层测试在任何机器上都必须全绿、不许 skip**；只有渲染层那几件许 skip，且须打印说明。

## 考虑过的方案

- **二值保守化（带内一律判不通过）**：立场最干净，但会把好件挡下来，逼模型重试至多 2 次后报生成失败。主力环境上带内是常态：#55 自报的空白之一就是「页数 29–31 打 30 阈值必落带内」，任何推算页数横跨页数阈值的长文书**结构上必然**落带内；于是「出一版」会高频失败，等于换个方式重现今天的病。**它也正是「需人眼件不落盘」的真身**：不落盘不是保守立场，是这个方案换了个名字。
- **二值宽松化（带内一律判通过，只写披露项）**：legal-skills 记录的事故形态（「NOT_VERIFIED 整批移交用户」）。列在这里是为了让它被明确否掉；三值与它的分别是**不确定性进了结论字段本身**，没有任何下游读者（模型、脚本、退出码）能把它当通过。
- **给阈值加缓冲带**（即使 `T >= hi`，贴近阈值 5% 以内也判需人眼）：防的是推算模型自身的系统偏差，但 #55 与 #60 已经把那个偏差量掉了：两把真尺子间距 ≤0.1 磅，且每一件都窄于推算区间宽度，区间已把渲染器方差整个包住。再加缓冲带等于对同一个不确定性收两次费，且引入一个拍脑袋的常数。
- **在图的生成条目里记这一档**（只在需人眼时出现的可选键）：认真考虑过，因为本决定**自己制造了一个新歧义**（见后果）。律师裁定不记：结论住审查报告一处，条目已经指着那份报告；需人眼是回合内的信息，图记的是跨回合的事实。加键还会诱使后来者把它做成第四种节点状态，而节点状态由 ADR-0003 定为「只算不存」。
- **带内也触发重试**（模型改短标记试图出带）：否掉的理由不是成本。不通过时缩短标记值得：已知越界，改了确实变好；带内时不是：真值可能离阈值很远，模型把律师要的表述砍短，换来的只是一个它看不见的数字挪了位置。损失落在文书内容上，是本项目最不肯让模型碰的地方。
- **渲染点值落在推算区间外时判退出码 2**（推算模型对这件文书不成立、拒绝出结论）：**它只会阻断唯一能发现这件事的人**。律师那台机器永远没有渲染器、永远触发不到这条，只有开发会话与 Windows 回归跑会撞见；做成阻断等于惩罚发现者，而律师那边照旧拿到一个可能错的结论。
- **把实现拆成多张票分批合并**：中间态是**已被否掉的方案本身**：先删 `CannotRun` 里的「无渲染后端」再改值域，中间会有一段窗口门禁在没有渲染器时返回通过，那就是二值宽松化；反过来先改值域再删 `CannotRun`，需人眼在主力环境上根本触发不到。故实现票一张、一个 PR（[#62](https://github.com/f4de01/lawyer-workbench-v3/issues/62)）。
- **mac + Word 建渲染通道**：API 有，但无人值守不成立（#56 一手文档：TCC 非 MDM 无法预授权、Office 沙箱按文件授权、微软原文 "cannot run unattended"、无 headless 须有 Aqua 登录会话、枚举值与 Windows 不同），判为不值得建。
- **LibreOffice 作为必装项 / WPS 的 CUPS 虚拟打印机管线 / 两地分工（律师机出 DOCX、开发机过门禁）**：地图 #54 的 Out of scope 有逐条理由。LibreOffice 另有一条硬伤：**CJK 行距的 Word 兼容修复 26.2 才落地，早期版本系统性少算页数**，量页面几何的东西不能用它；它作为机会性后端之一仍在视野里，只是不作前提。

## 后果

- **「已生成」不再唯一等于「过了门禁」。** 在今天落盘即通过，所以图里「已生成」恒等于「过了门禁」；三值上台且图不记这一档之后，它不再唯一，判断依据只在审查报告里。这是「图不记这一档」这个选择的代价，原样记在这里。也正因为鸡蛋全放进审查报告这一个篮子，须目验清单才必须是结构而不是散文。
- **`CONTEXT.md` 四处已改**：「版式门禁」改写（「结论只有通过与不通过」「没有渲染能力时明确报错，不降级」两句失效）、新增「需人眼」词条、「生成」末句改为「通过与需人眼落盘」、「审查报告」加「结论为需人眼时开头另有一段须目验清单」。
- **ADR-0006 逐处被取代**（该 ADR 保持 `accepted`，大半篇幅是转换器的决定、一个字不动）：「我们决定」里版式门禁那一条（真实渲染前提、无渲染后端报错）；「考虑过的方案」末两条（「不过仍落盘」的判断**保留**，「无 Word 时降级为只做静态检查」的**判断保留、降级的定义随门禁本体改**）；「后果」里「若不同机…门禁的降级策略须重议」那句；2026-09-06 附注 (1) 里「门禁在沙箱里只能报无渲染后端」那句。Codex 沙箱里起不来 Word 从此不是错误，门禁照常给结论。
- **ADR-0015 的「缺 Word 即 fail 不 skip」口径随之改**（见上）。
- **PyMuPDF 是一件冻在 EOL 版本上的编译依赖**：1.26.5 是 3.9 线的最后一版，1.26.6 起 `Requires-Python >=3.10`、cp39 轮子没了，在 3.9 上 pip 不报错、直接钉死在 1.26.5。只要底线是 3.9，它就永远不会再更新，这给「降为可选」又添一条理由。
- **雾里留着两条，本 ADR 不解**：mac 上的字体替换与 Windows 不是同一套，而 mac 上又没有可无人值守的渲染通道，所以量不到；但它**不影响门禁本体**，因为推算层根本不碰字体文件，它只决定「渲染层这个机会性加信到底能加多少信」，而 #60 已把那个上限压得很低。另一条：推算器的判据要不要回流进转换器的最小集（例如限制单格字数）：第三档不重试之后，「写 Markdown 时就把标记改短」成了唯一的杠杆，这条因此比原来更要紧。

## 2026-09-08 附注（实现票 #62 落地时补的两条实测）

本 ADR 引 #55 的「25 件样本上页数 / 空白页 / 最大行高 25/25 落在推算区间内」作为「推算能替代渲染」的依据。实现时按 #59 第 4 条造那三件推算回归件，第 26 件就把那批样本的一个盲区照了出来，两条都记在这里：

1. **原型推算器在长文书上系统性多算页数，真值落在区间外。** 200 段的回归件 Word 与 WPS 都是 30 页，原型推算给的下界是 33 页（150 段件实测 23 页、下界 25 页）。原因是分页模型把放不下的段落整段挪到下一页，而 Word 在行边界上拆段：每段浪费一次，误差随篇幅累积。25 件样本几乎都是一两页的短件，所以从没暴露。改法是按行拆页，改后 150 段件下界 23、200 段件下界 30，两件的真值都进了区间。方向上原来是危险的：多算页数会把好件判成不通过，堵的是出件。

2. **页数下界因此再让一档余量。** 改后下界正好压在实测那一行数上，一格余量都没有；而 `lineRule=auto` 的行高由真实字体的 ascent / descent 决定，律师那台机器的替换字体与开发机不是同一套（见本 ADR 后果段留着的两条雾之一），行高小一点整篇就少一页。下界因此按 5% 比例放宽、四舍五入到整页：短件不因此变宽，23 页让一页、30 页让两页。上界本来就松（30 页件上界 38），不动。

这两条不改本 ADR 的任何决定，它们正是「fixture 的角色是一致性测试」那一条在起作用：三件回归件钉的是推算区间而不是门禁结论，所以它们照出的是推算器自己的毛病。三件的真值都由 Word 与 WPS 各量一次冻进 `tests/loo0ng-to-docx/test_layout_estimate.py`，两列逐件相同，再次符合 #60 的结论。
