# 回合只有一个入口，确认是对话里的一句话，以留痕与可逆替代入口门

ADR-0008 把主循环定成三个入口，理由之一是「确认与不适用必须是入口，不是句子」：律师专权要落在 harness 的 user-invoked 门上，legal-skills 的教训是提示词保护在长会话里不可靠。清单票上律师从使用体验反对：一个节点的文书由一个对话负责，在对话里出件、补事实、要求重出，最后一句"确认"或"不适用"结束节点也结束对话；出件之后还要另打一个名字拍板，过于复杂。这与 `CONTEXT.md`「回合」条一字不差，也与 Matt 的 `implement` 同形（一个 skill 驱动整段，人的裁定是对话里一句）。

我们决定：

- **出一版与拍板合成一个入口 `loo0ng-doit`**（显示名"办节点"）。自由文本 = 动作 + 节点 + 补充：「出一版 X」「X 我自己写好了」「确认 X」「X 不适用」「模块 Y 不适用」。一个对话里：出件 → 回显审查报告要点与待裁定项 → 律师补事实、要求重出 → 律师说「确认」或「不适用」→ 落条目、回显、对话结束。隔夜再拍板是新对话 `loo0ng-doit 确认 X`，同一个名字。主循环由此是两个入口加一个路由。
- **三条留痕规则替代入口门**：（a）确认与不适用条目原样存律师那句话，`图视图.md` 显示它；（b）只在律师明确说出「确认」「不适用」且指向本节点时落条目，从推断、从"看起来没问题"不落；（c）同一对话第二次「出一版」指向另一节点仍拒绝。
- **仍然先出件再问**：缺项列进审查报告，律师在对话里答一句成律师陈述再重出；生成中途不停下来问。ADR-0008 这条不动。

为什么站得住：ADR-0008 自己强制了一回合一对话，会话被压到一个节点长，legal-skills 那个"长会话里漂移"的前提已被拆掉；ADR-0002 把保护落在数据层（条目只增、已确认后重出回到已生成），一次错误的确认不是破坏性动作，看得见、盖得掉。

## 考虑过的方案

- 保留 `decide` 入口、出件收尾提示律师去打它：正是律师反对的复杂度。
- 合并但把确认做成引擎的"律师专用参数"：模型同样能填，不比留痕更硬。

## 后果

- ADR-0008 的「三个入口」「确认与不适用必须是入口」两条被本 ADR 取代，其余条款不变。
- Codex 侧确认从"硬门"退到"留痕"；出现一次 agent 自行落确认的真实事故时，再议把确认条目改为需律师在视图上签一笔。
- 路由的决策树"下一句"全部指向 `loo0ng-doit`。
