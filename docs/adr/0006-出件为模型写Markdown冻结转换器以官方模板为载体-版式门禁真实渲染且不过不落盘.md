# 出件 = 模型写 Markdown、冻结转换器以官方模板为载体；版式门禁真实渲染、不过不落盘

2.0 只有一条出件通道：模型产槽位值、`fill-docx.py` 写进模板。代价记在通用裁定台账 #8–#11：每遇一种新版式就要在脚本里开一个口子；legal-skills 在同一路线上走到「连续 5 轮返工、QA 清单次日勘误」。handoff §2.3 判 3.0 从「agent 直接产出文书」这一端出发。调研《「先 Markdown 再 DOCX」中间层的必要性调研》（`docs/research/md-first-必要性调研.md`）的结论是：**Markdown 本身不是必要条件，必要的是「冻结的确定性转换步骤 + 官方模板作为版式载体」**；Markdown 作为这一步的输入格式，赢在可审查（律师与第二个 agent 直接读、按段落引用）与局部重试（改一行重转、其余字节不变），代价只是表达力，而合并单元格、列宽、行高都能由转换器约定一次性覆盖。唯一像样的替代 docx-js 不能打开模板，19 件模板的版式要在代码里复刻并长期维护。

我们决定：

- **默认通道**：模型只写 Markdown（转换器定义的最小集），冻结的转换器打开该节点的官方模板、清 body 只留 sectPr、按模板字体写入段与表；收尾内置台账 #10、#11 两条确定性规则（清元数据；表格之后必留一个空段）。合并单元格与列宽、行高由转换器的约定覆盖，数值照抄模板，不引入填充器。
- **版式门禁**独立于转换器、只读、真实渲染（Word COM 出 PDF，PyMuPDF 检查）加静态检查。**fail-closed**：转换与门禁在临时位置完成，通过后才一次性写入案件工作区；不过则非零退出，agent 改 Markdown 重转重检至多 2 次，仍不过就报生成失败，把门禁结果原文交给律师，不交出不合格件。没有渲染后端时明确报错、拒绝出件，不静默降级为静态检查。
- **检查项分两级**。不通过项（客观几何与结构）：行高与页数阈值（长标记撑列）、空白页（只有页码的页也算）、表宽超过页面可用宽、页脚 PAGE 域丢失或被写死、表格直接接 sectPr、docProps 残留作者 / 修改者 / 打印时间、正文残留模板原文片段。披露项（写进审查报告、不判不通过）：空单元格坐标（台账 #13 纸质要件）、请求字体 ≠ 嵌入字体、页数。不做姓名词表。
- **确定性规则的进入路径**：真实案件里门禁或律师发现的一次事故 → 记入通用裁定台账 → 一条规则加一对 fixture（故障件必拦、正常件必过）进转换器收尾。填充器不引入，「门禁前不写填充器」保留。
- **验收**：五种故障样例必拦、正常件必过，作为门禁命令行接口上的自动测试；19 件模板各出一份甲乙丙占位件全部通过；4 件含合并单元格的模板出件与模板同形；真实案件里 Claude Code 与 Codex 各触发一次。验收由门禁跑 fixture 得出，不采信生成侧自报通过。
- **归属**：一个参考 skill 持转换器与门禁两个命令行工具，互不 import；门禁可单独对任意 DOCX 跑。律师兜底自写的文书，门禁只披露不阻断。命名留给「编排层与参考层的 skill 清单」。

## 考虑过的方案

- 模型写 docx-js（Anthropic 官方 docx skill 新建文档的做法）：合并单元格、eastAsia 字体、PAGE 域都是一等 API，但不能打开既有文件，只能用占位符补丁；中间物是代码，律师不可审；每次输出时间戳必变。
- 模型直接编辑 OOXML（Anthropic 官方 docx skill 编辑既有文档的做法）：保真最高，但 Word 把可见文本切碎成多个 run，直接替换命中 0 处；官方配套脚本许可禁止派生分发。
- 模型每次现写 python-docx 代码：与冻结转换器同库同产出，只是把转换器交给模型每次重写，确定性与可审查性都退回代码层。
- 槽位填充（2.0 与 legal-skills 路线）：已判门禁前不做。
- HTML → Word COM 另存：样式降级，Word 写入本机用户名。
- 门禁不过仍落盘为新版本、审查报告写不通过：把不合格件交给律师，legal-skills 的教训是「NOT_VERIFIED 整批移交用户」是反模式。
- 无 Word 时降级为只做静态检查：legal-skills 反复记录的事故形态都是静默降级。

## 后果

- 律师主循环里「生成失败」是可见结果之一，律师可兜底自写；兜底件永不被 agent 改动（ADR-0002）。
- 模型只能写转换器最小集里的 Markdown，最小集与合并单元格约定是 skill 包的一部分。
- 假设律师使用 Codex 的机器与开发机相同、有 Word；若不同机，「无渲染后端」会是常态，门禁的降级策略须重议。Codex 的 shell 默认超时 10 s、上限 30 s，单件门禁在预算内；19 件模板回归只在开发侧跑。
- 续改律师已在 Word 里改过的成品需要另一条 OOXML 编辑通道，未决，记在地图「尚未指明」。

## 附注（2026-09-05，ADR-0015）

「五种故障样例必拦、正常件必过」的 fixture 落点是仓库根 `tests/loo0ng-to-docx/`，不随 skill 分发；缺 Word COM 时测试 fail 不 skip。「一次事故 + 一对 fixture」的进入路径推广到全部 skill。
