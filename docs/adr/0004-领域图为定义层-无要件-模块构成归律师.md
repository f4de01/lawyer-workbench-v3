# 领域图为定义层，图里没有要件，模块构成由律师裁定

ADR-0003 把图定为单一 JSON 状态文档，同时留下三个前提："要件属于模块定义"、"没有删除"、"初始化产出空图"。做模块的来源与定义/实例分层时，这三个前提都被重裁。我们决定：

- **定义层就是一张图**。模块与节点的通用定义不另存 Markdown、YAML 或任何摘要文件，而是一张没有条目、不含案件内容的图，称为**领域图**，与案件图同一格式、同一引擎读写。一个领域一张领域图，随 skill 包内置，也可以独立交付。skill 包本身不含任何领域语义，没有领域图也能从空图起手、由律师用自然语言长出整张图。
- **图里没有要件**。2.0 流程模型逐节点的"载明要件清单"是从指引与模板摘出来的中间层，正是 2.0 里那类不便查看的清单文件。3.0 不维护任何形式的要件清单、检查清单、出处指针：agent 生成与审查时直接读空白模板、指引手册原文、过往文书与材料。领域图的节点只有默认标题、空白模板属性、顺序，模块只有名称。两份指引手册合计约两万一千字，agent 一次读完，"帮它定位章节"的指针没有功能。
- **领域目录只有原件**。一个领域的内容单元 = 领域图 + 官方模板 docx 原件 + 指引手册 docx 原文，三样都是原件或图，没有摘要层。`knowledge/` 下除官方模板与指引手册外的一切（流程模型、文书卡、登记表、规范、裁定台账）只作参考，不进 3.0 设计；模板挂哪个节点由领域图的空白模板属性承担，登记表不再维护。
- **模块构成归律师**。节点可新增、改标题、排序、跨模块移动、改空白模板属性，永不删除，不要了走不适用；模块可新增、改名、排序，**空模块可删**（节点先移走，不丢任何条目）。律师在案件图上、开发者在领域图与交付图上，用同一个引擎、同一套操作。
- **惰性只约束 agent**。初始化起手图三选一：空图、整份领域图、开发者交付的定制图。人选整份领域图起手是人的决定，不受惰性约束；agent 在其上仍只补不铺。ADR-0003 拒绝的是 agent 自动带入整个模块，不是人主动选择完整图。
- **硬边界 2 不动**。律师在案件会话里对图构成的一切修改都落在案件工作区的案件图里，永不写仓库。案件图反哺领域图走开发会话：剔除条目、去案件化、过第二双眼。
- **审查报告只对文书负责**。它载明生成依据、存疑点、待律师裁定或修改之处、通过或不通过的理由；一切本来会写进文书正文的标注都移到这里，文书本体始终以直接可提交为目标。

## 考虑过的方案

- 定义写 Markdown、引擎不读、agent 读完把参数交给引擎，图里节点带定义指针：要件进图后同一份内容会有 Markdown 与 JSON 两处；要件退场后 Markdown 层只剩标题与模板名，不值得第二种格式。
- 案件工作区里另设"案件级定义"目录：让"定义"有两处存放地，反哺路径也变长。
- 要件作为节点属性进图、逐条带来源并做行级保护：把 2.0 的清单层原样搬进图，与"不冗余"和"读原文"都相悖。
- 节点带出处指针（"指引 一（一）"）：素材体量小到 agent 整读，指针无功能；日后真实生成出现读错章节的事故再加。
- 维持 ADR-0003"模块也不能删"：律师无法把节点重新归类后清掉空壳模块，构成裁判权不完整。

## 后果

- ADR-0003 的"要件属于模块定义"、"没有删除"（模块部分）、"初始化产出空图"三句由本 ADR 取代；其余不变。
- 案件图顶层「领域」一项记领域图的名字（不是路径），路由按名字在 skill 包里找领域图；路由先读案件图，案件图里没有的才去领域图里找。
- 图存档与领域图格式同源：领域图就是剔除条目、去案件化的图存档。图存档票在此前提上定判据与时点。
- 初始化票收"起手图三选一"；skill 清单票定领域目录归哪个参考 skill 拥有；反哺路径成为独立票。
- `docs/指引手册/` 两份 docx 与 `knowledge/模板/` 19 件原件最终随领域目录走；具体搬迁在 skill 清单定下后做。

## 附注（2026-09-05，ADR-0012）

后果里"领域图就是剔除条目、去案件化的图存档"随 ADR-0011 失效（图存档已改义为派生视图的机器可读形态）。案件图反哺领域图的路径由 ADR-0012 定，正式词为「回流」。
