## Destination（候选，制图时先裁）

一份可交给 `/to-spec` 的地图：图的数据模型与归属已定，节点的状态与律师动作已定，初始化与路由两个编排 skill 的行为已定，编排层与参考层的 skill 清单已定，文书出件机制与验收项已定，图存档对可视化插件的接口已定。可视化插件本体不在此地图内。

## Notes

- 每个会话先读 `CONTEXT.md`、`docs/adr/`、`AGENTS.md` 两条硬边界。
- 调用 domain-modeling 时遇到 `knowledge/` 里的"模块""节点"按素材原义理解再映射，不改素材。
- 研究票读 `docs/research/legal-skills-独立调研.md` 与 `…交叉对比.md`，不重新克隆外部仓库。
- 环境：Windows 11、中文路径、PowerShell 为主；任何依赖 Unix 文件锁或 LibreOffice 字体的做法都要在本机验证过才算数。
- 首个领域是破产，但图、模块、节点的模型不得写死破产语义。

## 可以现在开的票

按依赖顺序。类型按 wayfinder 四类。

1. **节点的状态与律师动作**（grilling，前沿）
   问题：一个节点从出现到完成经过哪些状态；生成、确认、审批各由谁发起、谁落盘；一个节点对应一份文书时，多份文书同出的场景（如接受指定时的承诺书、团队信息、工作计划）如何表达；节点完成的判据是什么。
   借鉴 J3：律师写过的内容 AI 永不覆盖，以此替代逐项确认。
2. **图的存放格式与写权**（grilling，被 1 阻塞）
   问题：图在案件工作区内以什么文件形态存在；节点排序与模块排序如何表示；谁能写（律师、agent、哪些 skill）；惰性补全的触发条件；并发与原子写。
   借鉴 J5；避雷 B2、B9。
3. **模块的来源与定义/实例分层**（grilling，被 1 阻塞）
   问题：模块定义（通用，可从指南手册、agent、自然语言产出）放仓库 `knowledge/` 还是别处；模块实例进图后与定义的关系；律师在案件会话里增删模块如何不违反硬边界 2；模块的粒度由什么决定。
4. **文书出件机制与验收项**（grilling，前沿）
   问题：默认走模型写全文再通用转换（J2）；版式门禁从第一天就有、只读、不过不覆盖（J1）；门禁检查项 = 裁定台账 #8–#11 的五种事故 + 残留第三方信息；何种事故才引入确定性脚本（B1）。
5. **案件工作区目录规范与初始化预处理**（grilling，被 2 阻塞）
   问题：目录层次；已有材料、模板、文书、指南的归档规则；空案件的初始形态；目录规范写成 YAML 预设（J4）；既有案件工作区的迁移处置表（J6）。
6. **路由的定位机制**（prototype，被 2 阻塞）
   问题：地图部分照 ask-matt 写法；定位部分读图回答"当前节点、上一完成、下一任务"；给出提示词编排的形式。原型：手写一张小图，让路由桩子回答三问。
7. **编排层与参考层的 skill 清单**（grilling，被 1、4 阻塞）
   问题：从律师一天的工作反推命令数与确认点；哪些成为编排 skill，哪些成为参考 skill；每个 skill 的 description 四要素（J10）；完成定义"在真实案件会话里被真实触发过一次"。
8. **图存档与可视化接口**（grilling，被 2 阻塞）
   问题："趋近完整"的判据与存档时点；存档格式对可视化插件暴露什么；呈现形态（官方 MCP 格式 / app）对存档格式的要求。
9. **Claude Code 侧 skill 分发与可视化承载的官方现状**（research，AFK，前沿）
   问题：官方 skill 打包与引用方式、`disable-model-invocation` 现行语义、MCP app 或等价可视化承载形式的现状。供 6、8 参考。
10. **既有案件工作区清点**（task，AFK，前沿）
    问题：清点仓库外案件工作区的数量、目录形态、文书数量级，只记录计数与结构，不记录任何案件内容。供 5 的迁移处置表使用。

阻塞边：2←1，3←1，5←2，6←2，7←1、4，8←2。
