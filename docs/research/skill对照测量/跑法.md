# skill 对照测量：怎么跑（Codex 桌面客户端，人工）

要回答的一问：**同一份文书，裸 agent 与走 skill，时间差在哪里、差多少，其中哪些是功能的价钱、哪些是纯损耗。**

这是 [#123](https://github.com/f4de01/lawyer-workbench-v3/issues/123) 缺的对照组。#123 只量了 skill 这一条路的内部分布，没有基线，所以「三分钟是不是该有的价格」当时答不了。

**范围只有 Codex 桌面客户端。** Claude Code 侧这一轮不跑。

---

## 一、三条腿，不是两条

只跑「裸 agent」与「完整 skill」两条，功能的价钱与机制的损耗会糊在一起，量完还得再吵一轮。三条腿把它切开：

| 腿 | 跑什么 | 产出 | 这一段差值说明什么 |
| --- | --- | --- | --- |
| **A 裸** | 裸 agent + 提示词 + 材料 + 模板 | 只有 `.docx` | 基线 |
| **B 裸补齐** | 同 A，但要求同样的产出面 | `.docx` + 审查报告 | **A→B = 功能的价钱**（多写的字） |
| **C skill** | `$loo0ng-doit 出一版` | 三件齐全 + 图条目 | **B→C = skill 机制本身的开销** |

B 是关键的一条。没有它，C 比 A 慢的部分会被整体记到「skill 太重」头上，而其中有一部分本来就是因为 C 多做了事。

---

## 二、喂料：三份互不相干的工作区

用合成种子，**不碰任何真实案件**。每条腿每一轮都用一份**全新**的工作区，跑完就扔——第二条腿不能看见第一条腿落下的文书。

在仓库根目录下，每跑一轮生一份：

```
python scripts/skill-eval.py --materialize 在办中
```

它会打印一个 `%TEMP%` 下的路径，里面是一份完整的合成工作区：20 份官方模板、1 份材料、2 条律师陈述、2 份已有文书、一张 12 模块 72 节点的图。

**目标节点固定为「管理人银行账户备案报告」**：它在图里条目为 0（还没出过件），带官方模板 `模板/官方/1-3.关于管理人银行账户备案的报告.docx`，正是「任务很简单，只需要填入几个信息」的那一类。别换节点，换了三条腿就没法比。

**A、B 两条腿要先动一处**：把工作区 `AGENTS.md` 里
`- 入口：loo0ng-setup-case（起手）、loo0ng-doit（办节点）、ask-loo0ng（问路）`
这一行删掉，免得裸 agent 顺着它自己找去调 skill。C 那一份原样不动。（这处删改要照实记进结果：两条腿的上下文因此差了一行。）

## 三、六个对话，交替着跑

每条腿跑 **2 轮**，共 6 个对话。顺序 **A B C A B C**，不是 AABBCC——服务端负载和限流在一天里会变，连着跑同一条腿会把那个漂移整个记到那条腿头上。

规矩：

- **模型固定 `gpt-5.6-sol`，强度固定一档，六轮一个字不许变。** 在桌面客户端的对话选择器里切，每开一个新对话都确认一遍——客户端的默认值来自 `~/.codex/config.toml`（本机是 `gpt-6-astra` / `medium`），忘了切就会静默跑成别的模型。`rollout分析.py` 会把每一轮实际用的模型与强度打出来，六轮不一致时直接告警，跑完先看这两行再看别的数。
- **强度选哪一档**：六轮统一 **medium**。理由是只换一个变量——模型已经从 [#123](https://github.com/f4de01/lawyer-workbench-v3/issues/123) 那组数的 `gpt-6-astra` 换成了 `gpt-5.6-sol`，强度再一起动，差值就没法归因。想看强度的影响，**在六轮之后另跑 A/B/C 各一轮 high**（3 个对话）作为加试，而不是整套重来。
- **一个对话只跑一条腿的一轮**，跑完就停，不追问、不纠正、不补话。中途想说什么，这一轮作废重来。
- 六轮之间**不改 `~/.codex/config.toml`**，尤其 `context_management` 保持现状（本机 `true`）。它现在是什么值，量出来的就是律师实际撞到的东西。跑之前把它抄下来记进结果。模型与强度走对话选择器，不必动配置文件。
- 每一轮**人工掐一个表**：从按回车到最后一个字出现。日志里的时间戳不含客户端排队，两个数摆在一起才看得出有没有排队。

## 四、量：不需要任何埋点

**Codex 桌面客户端把整个会话写成 JSONL，落在 `~/.codex/sessions/<年>/<月>/<日>/`。** 已核实：桌面客户端（`originator: "Codex Desktop"`）与 CLI 的日志结构完全一致，每行带毫秒时间戳，`custom_tool_call` 与 `custom_tool_call_output` 按 `call_id` 配对，每次模型响应有一条 `token_usage_record`。

六轮跑完，回到仓库根目录：

```
python docs/research/skill对照测量/rollout分析.py --list 10
```

按时间挑出那六份，然后：

```
python docs/research/skill对照测量/rollout分析.py <A1> <B1> <C1> <A2> <B2> <C2>
```

多于一份自动并排。单份看细账加 `-v`（逐条列出每次工具调用、耗时、退出码）。

它切出来的东西，与 #123 同一把刀（工具区间取并集，其余算模型）：

- **总墙钟 / 模型时间 / 工具时间 / 模型占比**
- **往返次数**与**工具调用次数**——这是「能不能少几次」那根自变量的直接读数
- **开场到第一次调用产品 CLI 的秒数**，即 #123 说的「开场整读」那一段
- **分段**：图引擎、转换器、门禁、归档、陈述各自的次数与耗时
- **非零退出的调用次数**——转换器退出码 1（稿子不在最小集里、表形与模板不合）与门禁不通过，都会在这里显形。**重试环路 #123 一次都没采到样**，它是目前最能解释 3 倍差的形状之一
- **被截断的输出次数**——桌面客户端的 `exec` 按 token 截断（`max_output_tokens: 7000`），而 `loo0ng-doit` 的 `SKILL.md` 是 20 KB、`loo0ng-to-docx` 加两份 references 是 25 KB，整读一份正文很可能一次读不完、模型分块重读。裸 agent 那条腿撞不上这个
- **token 账**：输入、其中命中缓存、未命中（真付）、平均每次往返未命中多少、输出、其中思考

最后这一项就是 Q4 那笔悬着的账：**`cached_input_tokens` 直接给出 Codex 侧的缓存命中率**。#123 那条「正文体量与总时长没有因果」的结论，证据是 Claude 侧 `cache_creation` 只付一次；Codex 侧从来没验过，而律师用的就是 Codex。命中率高，那条结论跟着成立；命中率低，46 KB 正文就是每次往返都在付，本票的答案会完全不同。

## 五、跑完把什么交回来

- 六份 rollout 的路径（**别贴日志本身**，里面有工作区绝对路径；`%TEMP%` 下的合成工作区不撞硬边界 1，但省得来回检查）
- `rollout分析.py` 的并排输出——**先看头两行的「模型 / 强度」**，六轮不一致的话别的数都不用看了
- 六个人工秒表读数
- `config.toml` 里 `context_management` 当时的值
- 三条腿各自**产出对不对**：A 有没有出 docx、B 的审查报告写全没有、C 三件齐不齐、图条目追加了没有。**跑歪了的轮次要标出来**——一条腿没干完活却很快，那个数不能用

## 六、这一票不做什么

- 不改任何产品代码、不改 `config.toml`。先量后调（地图 Notes「先量不先改」）。
- 不在 Claude Code 侧跑。
- 不裁「要不要动、动哪里」——那是 [#133](https://github.com/f4de01/lawyer-workbench-v3/issues/133) 的事，本票只交数。
