# skill 对照测量：怎么跑（Codex 桌面客户端，人工）

要回答的一问：**同一份文书，加上 skill 这一层到底多花了多少时间，其中哪些是参考 skill 的、哪些是编排的。**

这是 [#123](https://github.com/f4de01/lawyer-workbench-v3/issues/123) 缺的对照组。#123 只量了 skill 这一条路的内部分布，没有基线。

**范围只有 Codex 桌面客户端。** Claude Code 侧这一轮不跑。

---

## 〇、第一版跑法为什么废掉（2026-09-13，跑了四轮之后）

第一版按「裸 agent / 裸补齐产出 / 完整 skill」切三条腿，四轮下来全废，两个原因：

1. **靠提示词分不开腿。** 四件参考 skill 是 model-invocable 的，模型自己就够到了——两条本该「裸」的腿都跑了 `md2docx.py`、`gate.py`、`graph.py`。更狠的是第四轮：它自己去 `Get-Content ~/.agents/skills/loo0ng-doit/SKILL.md`，把**编排 skill 的正文**读了进来。**模型够得到盘上的一切。**
2. **`$loo0ng-doit` 在 Codex 上不解析。** 本机 206 份会话日志全扫过：三件编排 skill 从来没有进过「### Available skills」列表（`policy.allow_implicit_invocation: false` 把它们整个剔出目录），`$loo0ng-doit` 被点名 4 次、经 skill 机制加载 0 次。律师 mac 上那种「自称未加载但实际调用了」，是模型自己去读了文件顶上——不是抖动。

所以第二版**把变量挪到盘上**：三条腿的提示词 A 与 B 完全相同，只差 `~/.agents/skills/` 里放着什么。一步只动一个变量。

---

## 一、三条腿 = 工作区里带着什么 skill

**Codex 认项目级 skill 目录**：工作区下的 `.agents/skills/` 会成为一个 skill root（本轮实测，探针 skill 进了可用列表）。所以三条腿各自把要的 skill 带在自己的工作区里，**跑的人一条命令都不用敲，六轮之间也不用切任何东西**。

| 腿 | 工作区 `.agents/skills/` 里放什么 | 提示词 | 这一段差值说明什么 |
| --- | --- | --- | --- |
| **A 真裸** | 空（整个目录不建） | 直述提示词 | 基线 |
| **B 参考层** | 四件参考 skill | **同 A，一字不差** | **A→B = 四件参考 skill 的开销** |
| **C 编排** | 七件全带 | 替身提示词 | **B→C = 编排正文的开销** |

铺台子的人做三件（`可见性.py` 与 `cp` 各一次，跑的人不碰）：

1. **全局那套关掉一次**：`python 可见性.py --state off`，把 `~/.agents/skills/` 下七件搬走。不关掉，A 腿就不裸——2026-09-13 实测，一条本该裸的腿自己跑去 `Get-Content ~/.agents/skills/loo0ng-doit/SKILL.md`。跑完 `--state all` 还原。
2. **按腿把 skill 拷进各自工作区**的 `.agents/skills/`（真拷贝，不是 junction；拷完删掉 `__pycache__`）。
3. **切断工作区里指向本仓库的那条线**：工作区 `AGENTS.md` 第 2 行的「领域目录」原本指着仓库里的 `skills/loo0ng-domain/assets/破产`，模型顺着它就能摸到仓库里的全部 skill 正文。把领域目录拷进工作区（一份 `_领域破产`）、那一行改指它。改完 `grep -rl 律师工作台v3.0 <工作区>` 应当一个文件都不剩。

**C 腿仍要替身提示词**，因为 `policy.allow_implicit_invocation: false` 在项目级 root 下照样把三件编排 skill 剔出目录（本轮实测：C 的工作区带着七件，模型报出来的可用列表里只有四件参考）。写法照 `scripts/skill-eval.py` 的 `CODEX_STAND_IN`，路径改成工作区相对：

```
读 .agents/skills/loo0ng-doit/SKILL.md 并照做：<律师那句话>
```

## 二、喂料

合成种子，**不碰真实案件**。每轮一份全新工作区：

```
python scripts/skill-eval.py --materialize 在办中
```

**生完要搬出 `%TEMP%`。** `--materialize` 落在 `C:\Users\<你>\AppData\Local\Temp\` 下，而那是**隐藏目录**——Codex 桌面客户端的工作区选择器进不去，人也不好手点。搬到一个平常看得见的地方再跑，六份分别叫 A1/B1/C1/A2/B2/C2，选起来不会认错。跑完整个删掉。

**目标节点固定「管理人银行账户备案报告」**：条目为 0，挂着官方模板 `1-3`，正是「只需填几个信息」的那一类。别换节点。

工作区 `AGENTS.md` 里那行 `- 入口：loo0ng-setup-case…` **六份都保持原样**。第一版删过它，现在不必了——变量已经挪到盘上，而那一行本来就是律师机上的真实状态。

## 三、六个对话，交替着跑

每条腿 2 轮，共 6 个对话，顺序 **A B C A B C**。不要连着跑同一条腿：服务端负载一天里会漂，AABBCC 会把漂移整个记到某条腿头上。

规矩：

- **每开一个新对话，先在选择器里确认模型 `gpt-5.6-sol`、强度 `medium`。** 六轮一个字不许变。客户端默认值来自 `~/.codex/config.toml`（本机 `gpt-6-astra`），忘了切就静默跑错模型。`rollout分析.py` 会把每轮实际用的模型与强度打出来，不一致直接告警。
- **每一轮开跑前先切盘上状态**，跑完那一轮再切下一个。切错了那一轮作废。
- **一个对话只跑一轮**，跑完就停，不追问、不纠正、不补话。中途说了第二句，这一轮作废、重生一份工作区。
- 六轮之间**不改 `~/.codex/config.toml`**，`context_management` 保持现状（本机 `true`）。
- 每一轮**人工掐表**：按回车 → 最后一个字。日志时间戳不含客户端排队，两个数摆一起才看得出。
- **每一轮都要验收稿子**，不只掐表：槽位齐不齐、模板固定内容（法院全称、案号字轨）有没有被抹、有没有凭空编出来的日期或金额。第一版四轮里只有一轮的稿子可用（[#141](https://github.com/f4de01/lawyer-workbench-v3/issues/141)）——**「快」和「能用」是两回事，只量时间会得出错误结论。**

## 四、量：不需要任何埋点

**Codex 桌面客户端把整个会话写成 JSONL，落在 `~/.codex/sessions/<年>/<月>/<日>/`。** 已核实：桌面客户端（`originator: "Codex Desktop"`）与 CLI 结构一致，每行带毫秒时间戳，`custom_tool_call` 与 `custom_tool_call_output` 按 `call_id` 配对，每次模型响应带一条 `token_usage_record`。

```
python docs/research/skill对照测量/rollout分析.py --list 10
python docs/research/skill对照测量/rollout分析.py <A1> <B1> <C1> <A2> <B2> <C2>
```

切法与 #123 同一把刀（工具区间取并集，其余算模型）。读数：

- **模型 / 强度**（抬头两行，先看这个）
- 总墙钟 / 模型时间 / 工具时间 / 模型占比
- 往返次数与工具调用次数
- 开场到第一次调用产品 CLI 的秒数
- 分段：图引擎、转换器、门禁、归档、陈述各自次数与耗时
- **非零退出的调用次数**——转换器退出码 1 与门禁不通过的重试环路，#123 一次都没采到样
- **被截断的输出次数**——桌面客户端 `exec` 有 `max_output_tokens: 7000`，而 `loo0ng-doit` 正文 20 KB、`loo0ng-to-docx` 加两份 references 25 KB
- token 账，含缓存命中率

**缓存这一问第一版已经有答案了**：三轮命中率 89.2% / 95.0% / 95.4%，Codex 侧缓存正常，「46 KB 正文每次往返都在付」基本可以销。截断是真的，每轮 1～2 次。

## 五、跑完把什么交回来

- 六份 rollout 的路径（**别贴日志本身**）
- `rollout分析.py` 的并排输出——先看「模型 / 强度」两行
- 六个人工秒表读数
- **六份稿子的验收结论**（槽位、模板固定内容、有没有编事实），这一份喂给 [#141](https://github.com/f4de01/lawyer-workbench-v3/issues/141)
- `context_management` 当时的值
- 跑歪了的轮次要标出来——一条腿没干完活却很快，那个数不能用

## 六、这一票不做什么

- 不改任何产品代码、不改 `~/.codex/config.toml`。先量后调（地图 Notes「先量不先改」）。
- 不在 Claude Code 侧跑。
- 不裁「要不要动、动哪里」——那是 [#133](https://github.com/f4de01/lawyer-workbench-v3/issues/133) 的事，本票只交数。
