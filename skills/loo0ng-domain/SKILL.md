# 领域目录与雏形

一个领域的内容单元只有三样（ADR-0004）：领域图、官方模板 docx 原件、指引手册 docx 原文。三样都是原件或图，没有摘要层：agent 生成与审查时直接整读原文，不维护要件清单、检查清单、出处指针。本 skill 持有它们，并持有把指南变成图里模块与节点的唯一机制：雏形。CLI 是本目录的 `scripts/sketch.py`（Python 标准库，零依赖，不 import 图引擎）。

## 领域目录

```
<本目录>/assets/<领域名>/
├── 领域图.json     # 与案件图同格式、无条目、不含案件内容；节点可带一句话「时限」
├── 模板/           # 官方模板原件，文件名即空白模板属性里的「文件」
└── 指引手册/       # 通用指引手册原文
```

- 案件工作区找领域目录只看起手落在工作区 `AGENTS.md` 里的「领域目录」绝对路径；没有那一行就让律师跑 skill "loo0ng-setup-case"。引擎 `--domain` 收这个目录或其中的 `领域图.json`。
- 内置的领域是「破产」：`assets/破产/` 下 19 件官方模板与 2 份指引手册就位；领域图的 12 个模块、53 个节点由开发会话对这两份手册跑一次雏形长出（#30），19 件官方模板各挂在一个节点上，19 个节点带时限句。整份起手即这 12 个模块、前方为空。
- 模板与手册是 docx，harness 读不了：`python <本目录>/scripts/sketch.py docx-text <文件.docx>` 把正文打成纯文本（段落一行，表格一行一行、格间 `|`），整读它。
- 这三样之外什么都不放：既有案件的 `.doc`、生成空白模板、摘要与登记表都不进（硬边界 1，AGENTS.md 结构不变量 5）。

## 雏形：一个机制，三种来源

| 来源 | 在哪个会话 | 对着哪张图 | 谁拍板 | 产出 |
| --- | --- | --- | --- | --- |
| 案件级指南（工作区 `指南/`） | 律师会话，起手末尾或律师一句话 | 案件图 `图.json` | 律师 | 起手清单里的雏形，进案件图 |
| 通用指引手册（领域目录 `指引手册/`） | 开发会话 | 领域图 `--kind domain` | 开发者 | 领域图 |
| 案件图（回流，ADR-0012） | 开发会话 | 领域图 `--kind domain` | 开发者 | 领域图多出通用节点；步骤见 [references/回流.md](references/回流.md) |

四步，来源不同只换第一步读什么：

1. **整读来源**。指南或手册的每一份都整读，docx 用 `docx-text`。只从来源提，不从材料、不从常识铺节点：惰性只约束 agent，来源里没写的不提。
2. **写雏形文件**。按 [references/雏形格式.md](references/雏形格式.md) 写一份 JSON：每个模块带标题，每个节点带模块归属、默认标题、顺序（数组序）、空白模板属性（挂哪件官方模板，无则「无」）、时限句（规则见 [references/时限句.md](references/时限句.md)，没有就不写这个键）。写在 `%TEMP%` 下，**不落进工作区**：工作区里只有拍过板的东西。
3. **判重并回显**。`check` 只读，把清单原样读给律师：

   ```
   python <本目录>/scripts/sketch.py check --proposal <雏形.json> [--graph 图.json] [--domain <领域目录>]
   ```

   同名的（归一化后相同：不计空白、标点、全半角）已在图里，不重复提出；相似不同名的列进「待定」，让律师定是同一个还是新的；与领域图同名的标为「按领域图带入」，写入时沿用领域图的 id。清单之外不加自己的判断，也不先写再问。
4. **拍板后写入**。律师一句话（「照这个建」「都要」「第二个不要」）之后才跑 `apply`；起手时这句话是对整张起手清单说的。

   ```
   python <本目录>/scripts/sketch.py apply --proposal <雏形.json> [--graph 图.json] [--domain <领域目录>] [--as-new <标题>]...
   ```

   待定的按律师的话处理：是同一个就从雏形文件里删掉那条，是新的就 `--as-new <标题>`；有一条待定没定 `apply` 就整个拒、一字不写。写入逐条经引擎（默认取兄弟 skill "loo0ng-graph" 的 `scripts/graph.py`，装在别处用 `--engine` 指过去），引擎的回显照读给律师；引擎拒了哪条就照实转告，其余照写。案件图上时限句只回显不写（ADR-0016）：通用的由开发者回流时写进领域图，本案的具体日期是律师陈述，调用 skill "loo0ng-filing"。

## 判重与时限的规矩

- 判重只按标题，节点对节点、模块对模块；相似的判据是一方包含另一方，或归一化后相似度过阈值。阈值由脚本定，模型不调；律师说「这两个是一个」就删条，不改脚本。
- 雏形里的节点只有引擎认的四样：标题、空白模板、时限、（领域图上的）id。要件、出处指针、检查项都不进图（ADR-0004），生成与审查时读原文。
- 时限只记管理人自己在该节点上要守的、有天数或只有锚点的期限，去案件化原文含出处性质；「及时」与无明示期限不记；两源冲突同一句里两条都写。

## 领域图（只在开发会话）

领域图用同一引擎、同一雏形 CLI，加 `--kind domain`，可给稳定可读的 `id` 与时限句。领域图住本目录 `assets/`，只在开发会话里改、走分支 + PR（隐私钩子在 main 上守它，ADR-0014）；办案会话对它只读，硬边界 2。案件图里长出的通用节点回流进领域图的操作步骤在 [references/回流.md](references/回流.md)，律师会话里没有这个动作。

## 与邻居的边界

- 雏形写入之外的一切改图（改标题、调顺序、移动、不适用、追加条目）调用 skill "loo0ng-graph"；本 skill 不直接改 `图.json`。
- 指南进 `指南/` 是归档，调用 skill "loo0ng-filing"；本 skill 只读它。
- 起手时官方模板拷进工作区 `模板/官方/` 由 skill "loo0ng-setup-case" 做；出件读它由 skill "loo0ng-to-docx" 做；本 skill 只是原件的家。
- 本 skill 不含领域语义：判重、写入、读 docx 都不认「破产」两个字；换一个领域只换 `assets/` 下的目录。
