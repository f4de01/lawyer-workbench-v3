# 回流：把案件图里判为通用的模块与节点写进领域图

方向与对象只有一个：案件图的构成写进领域图。回的只有图的构成，节点、标题、归属、顺序、空白模板属性、时限句；不回条目、不回律师陈述里的裁定、不回「生成」空白模板；保留案件里的原 id；只回本领域的图。

ADR-0019 把它分成两条路，会话、时点、写的是哪一份、审查强度都不同：

| | 律师侧逐节点（默认路） | 开发侧批量 |
| --- | --- | --- |
| 在哪个会话 | 办案会话，当前目录是案件工作区 | 开发会话，当前目录是本仓库 |
| 时点 | 节点确认那一刻，一次一个节点 | 没有时点，开发者维护 skill 包时批量做 |
| 写的是 | 律师本机的**活图** `~/.loo0ng/领域/<领域>/领域图.json` | 随包分发的**出厂种子** `skills/loo0ng-domain/assets/<领域>/领域图.json` |
| 做什么用 | 律师这一个个案子累计出自己的领域图，下一个案子接着用 | 补这套机制上线前已确认的历史节点；开发者定制领域图后分发 |
| 谁拍板 | 律师一句话 | 开发者一句话 |
| 第二双眼 | **没有**（活图不进本仓库） | 有，PR 里 AFK 代理审 diff |
| 走不走雏形 | 不走，一次一个节点，直接经引擎 | 走，`from-case` 算出一批候选写成雏形文件 |

## 判为通用要两条都满足

1. **用过一次**：该节点在真实案件里至少有一版已确认文书。未生成、只生成未确认、不适用的都不是候选。模块的判据是其下至少一个节点满足这条。
2. **去掉案件事实后标题仍成立**：改写成通用标题后，第二个同领域案件读得懂、用得上。

律师侧第一条在确认那一刻天然成立（那一刻正是"至少有一版已确认"的时刻），第二条降为可用性要求，由 agent 提默认标题、律师拍板；开发侧第一条由 `from-case` 机械算，第二条由开发者改写标题时判。

## 律师侧：逐节点，在确认那一刻

在办案会话里做，由 skill "loo0ng-doit" 在确认之后驱动（那一问挂在它的收尾）。缺失判定、回显什么、写入的命令都在它的正文里；本篇只记这条路的规矩：

- **只对领域图里没有的节点问。** 判定是按 id 的反向减法，引擎已经算好了：`图视图.md` 里这个节点那一行的「来源」是「领域图」就一个字不问，是「案件」才问。写死成每次都问，就是把 2.0 的反复确认搬回来。
- **一次只问一个问题，两个默认值**：模块继承它在案件图里所在的那个，标题取去掉当事人、案号、金额、日期之后仍成立的写法（与本篇第 3 步开发侧那套改写是同一个口径）。
- **不问时限**（ADR-0019）。律师侧新增的节点没有时限属性，缺省；有通用规则的由开发者维护出厂种子时补。
- **未拍板不写**，与雏形机制同一条规矩：律师那一句之前活图一个字不动。
- **写入只经引擎**，`--kind domain` 指着活图那份 `领域图.json`；改模块、改标题、跨模块移动、新建或改名模块用的都是引擎现成的子命令，不新增 CLI。
- **没有第二双眼。** 活图在 skill 包之外、不进本仓库，硬边界 1 与隐私钩子都管不到它；去案件化在这条路上是可用性问题（别让 A 案当事人的名字出现在 B 案的图里），不是隐私门禁。进仓库的那一份仍要第二双眼，见下。

## 开发侧：批量，只在开发会话

只在开发会话做（ADR-0012）：当前目录是本仓库，开发者一句话给出案件工作区路径，agent 只读那份 `图.json`，写的是出厂种子。它现在做两件事：补这套机制上线前已确认的历史节点，以及开发者定制领域图后分发。

1. **开分支**。隐私钩子在 `main` 上拒绝触及领域图文件的提交（ADR-0014）。
2. **算候选**。只读案件图，按 id 做「案件图有、领域图没有」的减法，再筛至少一版已确认的：

   ```
   python skills/loo0ng-domain/scripts/sketch.py from-case --case <案件工作区>/图.json --domain skills/loo0ng-domain/assets/<领域> --out %TEMP%/回流.json
   ```

   产出是一份雏形文件：模块与节点保留原 id；已在领域图里的模块按领域图的标题指认（案件里改过名也不带）；官方空白模板原样带，生成空白模板改为「无」；没有时限。没有候选就什么都不写。
3. **去案件化改写**。逐条读候选标题，去掉案号、当事人、具体日期与本案特有的说法，改成通用标题；本案专有、第二个案件用不上的整条删掉。有通用规则的节点补上一句时限（取舍见 `时限句.md`）。改的只是那份雏形文件。
4. **判重回显**。对着领域图 `check --kind domain`，与领域图同名的不再提，相似的列为待定，由开发者定：

   ```
   python skills/loo0ng-domain/scripts/sketch.py check --proposal %TEMP%/回流.json --graph skills/loo0ng-domain/assets/<领域>/领域图.json --kind domain
   ```

5. **一句话拍板后写入**。

   ```
   python skills/loo0ng-domain/scripts/sketch.py apply --proposal %TEMP%/回流.json --graph skills/loo0ng-domain/assets/<领域>/领域图.json --kind domain [--as-new <标题>]...
   ```

   顺序要调用引擎的 `move-node` / `move-module`（`--kind domain`）；领域图节点改标题用 `rename-node`。
6. **验证**。`python skills/loo0ng-graph/scripts/graph.py --graph <领域图> --kind domain validate`；在测试工作区整份起手看视图。跑脚本层测试与三条校验，再跑两侧的用例「回流」（`python scripts/skill-eval.py --harness claude --case 回流`，Codex 侧同）。
7. **发布**。`npm run changeset`（minor：领域图的一次发布），提交、开 PR。
8. **第二双眼**。另一个会话的 AFK 代理审 diff，专查案件内容：姓名、公司、案号、金额、日期；隐私钩子只跑正则，不算第二双眼。开发者读报告后合并。

## 两条路都不做的

- 不给回流的节点换新 id：该案的前方会多出一个与自己重复的节点。
- 不动案件图：回流只读它；领域图改版也不改案件图任何字节，前方是按 id 的减法。
- 不回流案件里领域图节点的改名：领域图节点的标题由开发者直接用 `rename-node --kind domain` 改，那是对领域图的普通编辑。
- 开发侧那条没有时点、不自动触发；律师侧那条的时点只有确认那一刻，不在生成中间问，也不等结案。
