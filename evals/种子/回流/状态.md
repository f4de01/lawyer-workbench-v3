# 种子「回流」的状态

一个开发会话看得见的摊子（ADR-0012）：回流只在开发会话做，当前目录是本仓库、开发者一句话给出案件工作区的路径。跑器把 cwd 设在临时工作区，所以工作区根摆的不是六格，而是那个会话要用到的三样：

```
<工作区>/
├── 案件/          案件工作区，先照种子「在办中」回放一遍，再加两个律师自加节点
├── 领域图.json    skills/loo0ng-domain/assets/破产/领域图.json 的可写副本
└── 基线.json      回流之前的样子：案件图与领域图的 sha256、领域图的模块数与节点数
```

副本而不是仓库里那份原件：eval 只生不存（ADR-0015），一次跑不该动到 `skills/` 下的领域图。断言拿 `基线.json` 复核「回流只读案件图，案件图字节不变」与「领域图只多出一个节点」，节点数从基线里读、不硬写：下一次回流让领域图长大时，种子跟着长，用例不用改。

`案件/` 这一层的状态见种子「在办中」的 `状态.md`（真实破产领域目录整份起手、六格、`管理人承诺书及团队人员` 已确认、`管理人印章备案报告` 已生成未确认、两条律师陈述）。本种子在它之上加两个律师自加节点，都挂在领域图已有的模块「接管与调查」下：

| 节点 | 状态 | 是不是回流候选 |
| --- | --- | --- |
| 乙公司甲年乙月丙日厂区接管现场情况说明 | 已确认（一条生成、一条确认，原话「现场情况说明这份可以了，就这样定」） | 是 |
| 乙公司食堂承包合同解除请示 | 已生成（一条生成，没拍板） | 否，判据 (a) 要至少一版已确认 |

- 两个标题都带着本案的当事人与日期，去案件化才用得上：`乙公司`、`甲年乙月丙日` 都要去掉；`厂区` 去不去归模型判（实测两侧都判成本案特有、一并去掉），用例的断言只认核心词「接管现场情况说明」加「当事人和日期不在标题里」。
- 两个节点各有一个 `文书/<节点标题>/` 目录，里面一份合成的 `.md` 与同名 `-审查报告.md`，报告都是五段固定的形状。
- 领域图里已有的 72 个节点都在案件图里（整份起手），按 id 减法它们都不是候选；模块「接管与调查」也已在领域图里，回流时按领域图的标题指认。
- `python skills/loo0ng-domain/scripts/sketch.py from-case --case 案件/图.json --domain 领域图.json` 恰好提出一个候选，`tests/loo0ng-domain/test_seeds.py` 机械复核这一条。
- `案件/` 那一层由跑器自己的 `replay_seed` 摊出来（`scripts/skill-eval.py`），元文件名单只有那一份。
- 不含隐私检查器五类正则能命中的值：没有案号、没有手机号、没有身份证、没有统一社会信用代码、没有案件目录路径；当事人与法院一律写「甲」「乙」「丙」。

供用例「回流」：开发者一句话给路径，断言回显清单与拍板后的领域图。
